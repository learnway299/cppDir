# 05 - 开源工具链（辅助 AI 高效编程）

## 核心概念

开源工具不替代模型，而是补齐 **运行、检索、编排、评测、接入** 四件事，让 AI 编程更稳、更可控、可私有化。

```
本地/私有模型运行     代码检索与索引      Agent 编排
        \               |               /
         \              |              /
          ---- RAG / 向量库 / MCP ----
                     |
                   评测与门禁
```

> 下列产品生态迭代快，面试抓 **类别与解决的问题**，不必背版本号。

---

## 按用途分类

### 1. 本地 / 开源模型运行

| 工具 | 作用 |
|------|------|
| **Ollama** | 本机拉起开源模型，API 简单，适合隐私试点 |
| **llama.cpp** | 消费级硬件推理，量化部署常见底座 |
| **vLLM** | 高吞吐服务端推理，适合团队共享 GPU |
| **Hugging Face 生态** | 模型与数据集分发（合规需自审 License） |

**何时用**：代码不能出域、要做离线演示、对比「云模型 vs 本地模型」效果。

### 2. Agent / 应用编排

| 工具/框架 | 作用 |
|-----------|------|
| **LangChain / LangGraph** | 链式调用、状态图、工具 Agent 编排 |
| **LlamaIndex** | 偏数据接入与 RAG 管道 |
| **AutoGen / 类似多 Agent 框架** | 多角色协作实验 |
| **Semantic Kernel** | 企业向编排（微软生态常见） |
| **Dify 等应用平台** | 低代码搭 RAG/Agent 应用 |

面试口径：框架解决的是 **胶水与状态**，质量仍取决于检索、工具与评测。

### 3. 代码检索、结构与「给 Agent 的眼睛」

| 工具 | 作用 |
|------|------|
| **ripgrep (rg)** | 极速文本搜索，几乎所有 Agent 的底盘 |
| **tree-sitter** | 增量解析 AST，结构化导航 |
| **clangd / 语言服务器** | 跳定义、诊断，可被工具封装 |
| **ast-grep** | 结构化搜索替换，适合大规模一致改动 |
| **Sourcegraph（含开源组件生态）** | 大库代码智能搜索（部署形态看版本） |
| **universal-ctags / 符号索引** | 轻量符号库 |

### 4. RAG 组件

| 组件 | 例子 | 作用 |
|------|------|------|
| 向量库 | FAISS、Chroma、Qdrant、Milvus | 存 embedding，近邻检索 |
| 切分 | 按文件/函数/标题 chunk | 避免片段过碎或过整 |
| 重排 | reranker 模型 | 提升 Top-K 质量 |
| 文档加载 | 代码 + Markdown + API doc | 统一语料 |

Coding RAG 最佳实践：**符号检索为主，向量为辅**。

### 5. 评测、门禁与质量

| 思路/工具 | 作用 |
|-----------|------|
| **单元测试 / CI** | 最硬的 Eval（Agent 是否完成的金标准） |
| **promptfoo 等** | Prompt/Agent 回归评测 |
| **RAGAS 类指标** | RAG 答案忠实度/相关性（文档问答更常见） |
| **静态分析** | clang-tidy、Sanitizers 接在 Agent 后 |

### 6. 规范与仓库内「AI 说明书」

| 实践 | 作用 |
|------|------|
| **AGENTS.md / RULES / .cursor/rules** | 项目级约束与命令 |
| **EditorConfig / clang-format** | 减少风格拉扯 |
| **pre-commit / secret scan** | 防密钥进提交与上下文 |

### 7. MCP 与扩展生态

- 将浏览器、文档站、数据库只读查询、issue 系统做成 MCP Server  
- IDE / Agent 主机按需连接 → **可插拔上下文**  
- 面试强调：MCP 降低集成成本，不自动保证安全（仍要鉴权与权限）

### 8. 数据与实验跟踪（加分项）

| 工具类型 | 作用 |
|----------|------|
| LangSmith / 开源 tracing | 追踪 Agent 轨迹、工具调用 |
| 数据集版本管理 | 回归「这类 bug AI 还会不会修」 |

---

## 怎么组合（最小可行）

**个人隐私向**：Ollama + ripgrep + 本地 Rules + 单测门禁  

**团队云向**：强模型 API + 混合代码索引 + MCP 连内部文档 + CI  

**企业合规向**：私有 vLLM + 内网向量库 + DLP/密钥扫描 + 人工审批高风险工具  

---

## 常见面试题

**Q1：列举开源工具如何提升 AI 编程效率。**  
按「运行、检索、编排、评测、接入」五类各举 1～2 个，并说明解决什么瓶颈。

**Q2：只有大模型没有检索行不行？**  
能写通用样板；私有仓库、内部 API、最新重构不行。检索与 LSP 是效率放大器。

**Q3：LangChain 能保证 Agent 质量吗？**  
不能。它加速组装；质量看工具设计、上下文、测试与评测集。

**Q4：本地模型一定更安全吗？**  
降低数据出域风险，但仍有日志落盘、插件泄密、提示注入。安全是体系，不是「本地」二字。

---

## 实战要点

- 先接上 **搜索 + 测试**，再堆框架。  
- 评估工具时问：它缩短的是「找代码」还是「改对代码」？  
- 开源 License 与模型商用条款要分开看。
