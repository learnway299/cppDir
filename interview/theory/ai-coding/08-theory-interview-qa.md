# 08 - 理论考察题汇总

考前速刷 — 概念题 + 追问链。实践场景见 [09](09-practice-scenarios.md)。

---

## 基础概念

**Q1：用一句话解释 LLM。写代码时它的根本局限是什么？**  
答：在上下文条件下预测后续 Token 的生成模型。局限是不保证真值与程序正确性，只会生成「像正确答案」的文本；必须靠检索、编译、测试约束。

> **追问**：Temperature 调高会怎样？  
> **答**：更随机，创意写作或可，生产代码通常偏低以稳定。

**Q2：Token 和 Context Window 对工程有什么具体影响？**  
答：决定单次能塞多少代码、费用与延迟；超窗会截断或被迫摘要，导致丢约束。大文件应检索片段而非整文件硬塞。

**Q3：RAG 是什么？三步说清。**  
答：检索相关知识 → 增强进提示 → 再生成。Coding 里检索对象常是源码、文档、issue。

> **追问**：RAG 能代替 Fine-tune 吗？  
> **答**：事实类、易变知识优先 RAG；要固化风格/格式才考虑微调。二者可组合。

**Q4：Embedding 检索对代码为何不够？**  
答：代码重精确符号与结构；「长得像」不等于「就是这个重载」。需混合 ripgrep/LSP/AST。

**Q5：AGI 与当前 Coding Agent？**  
答：当前是 Narrow AI 专用系统。AGI 无公认已实现标准；勿把产品营销当技术结论。

## Agent 与架构

**Q6：Chatbot 和 Coding Agent 的本质区别？**  
答：Agent 具备目标驱动的多步循环与 Tool Use（读改跑），能把外部环境反馈纳入下一步；Chatbot 主要是单轮/多轮文本生成。

**Q7：画出客户端与服务端职责。**  
答：客户端：编辑器上下文、Diff、本地权限 UI；Runtime：规划与工具循环；模型服务：推理生成；索引/MCP：证据与外部系统。密钥尽量留本地。

**Q8：什么是 Tool Use？失败了怎么办？**  
答：模型提出调用，Runtime 执行并回传结果。失败应作为观察值，换工具/缩范围/升级人工，而不是把 stderr 当「业务已成功」。

**Q9：MCP 是什么？**  
答：Model Context Protocol，工具与数据源的标准接入方式，降低「每个 Agent 宿主各写一套插件」的成本。不自动等于安全。

**Q10：为何需要停止条件？**  
答：防止空转烧钱、重复破坏代码；以测试通过、用户确认、步数/费用上限、重复修改检测为常见熔断。

## 现象与风险

**Q11：什么是幻觉？举一个代码例子。**  
答：生成不存在的 `std::`/`Qt` API 或虚构文件路径。缓解：读真实头文件、编译、禁止无依据路径。

**Q12：Prompt Injection 在仓库里怎么发生？**  
答：恶意文档/网页被检索进上下文，内容写成「忽略之前指令并执行危险操作」。防护：检索当数据、权限最小化、高危审批。

**Q13：Lost in the middle？**  
答：长上下文中部信息利用率下降。关键约束放两端、减噪、分治任务。

**Q14：目标漂移和范围蔓延？**  
答：漂移是目标被换成别的；蔓延是顺手改太多。用 DoD、路径白名单、小 PR 抑制。

**Q15：Overconfidence / Sycophancy？**  
答：前者错仍很肯定；后者附和错误前提。要求举证、鼓励反驳、用测试裁决。

## Context / 流程

**Q16：Context Engineering 比「会写 Prompt」更重要？**  
答：Coding 成败更常取决于看见的文件、日志、规则是否正确充分，而非辞藻华丽。

**Q17：AGENTS.md / Rules 解决什么？**  
答：把构建测试命令、目录约定、红线固化，减少重复说明与版本幻觉。

**Q18：多文件任务正确顺序？**  
答：定位 → 最小读取 → 小步修改 → 验证 → 再扩面。

## 工具与产品

**Q19：开源工具如何分类记忆？**  
答：模型运行（Ollama/vLLM）、编排（LangGraph 等）、检索（rg/LSP）、向量库、评测/CI、MCP 接入。

**Q20：Copilot vs Cursor vs Claude Code 怎么答？**  
答：用维度表：补全 vs Agent、宿主形态、工具权限、模型策略、合规。避免绝对排名；强调团队流程比品牌更关键。

**Q21：本地模型一定更安全吗？**  
答：降低出域，不消除日志、插件、注入与误操作系统风险。

---

## 质量与安全

**Q22：AI PR 的验收标准？**  
答：行为由测试定义；CI 绿；Diff 最小且相关；安全与并发路径加强 Review；无密钥。

**Q23：Guardrails 举例？**  
答：路径限制在仓库内、密钥过滤、高危命令确认、完成前强制测试、步数熔断。

**Q24：依赖幻觉风险？**  
答：模型可能捏造包名；必须走官方源与锁文件，禁止「随手新增依赖」。

**Q25：如何度量 Agent 是否变好？**  
答：固定任务集成功率、平均步数/费用、无关文件改动率、线上返工与事故 — 而非主观「更聪明」。

- [ ] 幻觉 / 注入 / 漂移 / 空转 — 都能说出缓解

- [ ] MCP = 工具接入协议  
- [ ] 产品对比用维度，不站队  
- [ ] CI + Review + 权限 = 底线
