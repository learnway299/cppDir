# 09 - 实战场景考察

面试常考「你会怎么带 AI 干活」。按场景给 **标准答法结构**：目标 → 给 Agent 什么 → 约束 → 验收 → 翻车预案。

---

## 场景 1：修一个崩溃 / 失败测试

**题干**：线上崩溃或 CI 红了，让你用 AI 辅助定位并修复。

**答法**：

1. **固定复现**：最小用例、失败测试名、调用栈/ASan 日志原文  
2. **收窄范围**：相关模块路径、最近变更（git blame/log）  
3. **喂给 Agent**：栈 + 相关源文件 + 「只改修复所需」+ 验收命令  
4. **闭环**：编译 → 失败测转绿 → 必要时补回归测  
5. **Review**：是否治本、是否隐藏其他失败、有无无关重构  

**追问**：AI 给出的根因很自信但你怀疑错了？  
**答**：要求指出证据行号；自己用调试器/日志验证；让它提出可证伪实验。

---

## 场景 2：AI 乱改无关文件 / 大重构跑题

**现象**：Scope creep 或 Spec drift。

**处理**：

- 立刻 Reject 无关 Diff  
- 重写任务：路径白名单 + 「禁止格式化全文件」+ DoD  
- 拆成多个小 PR  
- Rules 里固化「最小 diff」原则  

**面试关键词**：范围锁、小步提交、DoD。

---

## 场景 3：从零实现小功能

**答法**：

1. 先让 Agent **列设计与文件影响面**（不直接写码）  
2. 人确认接口与错误处理  
3. 先写/生成测试（红）再实现（绿）  
4. 文档与特性开关（若需要）  
5. CI + Review  

**加分**：说明何时该拒绝 AI 的过度设计（多余抽象、新框架）。

---

## 场景 4：Code Review AI 生成的 PR

**检查清单（口述）**：

| 检查项 | 看什么 |
|--------|--------|
| 意图对齐 | 是否解决 issue，有无顺带「优化」 |
| 正确性 | 边界、错误路径、资源释放 |
| 并发/UB（C++） | 数据竞争、生命周期、悬空 |
| 安全 | 注入、路径遍历、密钥、依赖 |
| 可维护 | 命名、重复逻辑、测试价值 |
| 过程 | CI 是否真跑过；Diff 是否可读 |

**表态**：AI PR **不降标准**；对「看起来漂亮」的代码提高质疑。

---

## 场景 5：补测试 / 提覆盖率

**要点**：

- 说明要测的行为与失败注入点  
- 禁止无断言测试、禁止只测 mock 自身  
- 对遗留代码：先表征现状再锁定，避免「为绿而绿」  
- flaky 测试：隔离时间/顺序依赖，勿让 Agent 用 sleep 糊弄  

---

## 场景 6：重构（改结构，行为不变）

**标准流程**：

1. 建立表征测试或黄金数据集  
2. 明确不变式（公开 API、二进制兼容？）  
3. 分步重构，每步可回滚  
4. AI 负责机械变换（改名、抽函数），人负责边界  

**追问**：无测试的遗留模块？  
**答**：先补表征测或手动场景清单，再动刀；否则不算负责任重构。

---

## 场景 7：性能优化

**答法**：

1. 先测量（profiler）再优化，禁止 AI 空谈「更快」  
2. 把 profile 热点函数与汇编/采样图给 Agent  
3. 每次改动对比基准  
4. 警惕微优化破坏可读性与正确性  

---

## 场景 8：机密代码 / 不出域

**策略选项**：

- 企业私有模型端点 / VPC  
- 本地开源模型（接受质量落差）  
- 脱敏样本 + 最小复现工程  
- 禁用 Agent 网络工具；忽略密钥路径  
- 合同与审计日志  

**面试金句**：安全是 **架构与流程**，不是勾选「本地」就结束。

---

## 场景 9：Agent 陷入空转（Thrashing）

**识别**：反复改同一函数、测试仍红、理由互相矛盾。

**处置**：

1. 停自动循环  
2. 缩小复现，人先定位一层  
3. 换策略：先读调用方、先写失败测试、换更强推理模型  
4. 检查上下文是否塞了过时文件  

---

## 场景 10：文档 / 设计说明

**用法**：AI 根据代码生成文档草稿 → 人核对与架构真相一致 → 标出「生成内容已人工确认」。

**风险**：把幻觉架构写进 Wiki。要求每个关键断言绑文件路径。

---

## 场景 11：依赖升级 / API 迁移

**答法**：

1. 官方迁移指南进 RAG/上下文  
2. ast-grep / 编译错误驱动批量修改  
3. 锁定版本号进 Rules，避免模型用旧 API「回忆」  
4. 全量测试 + 金丝雀  

---

## 场景 12：结对排障「浏览器能开、客户端不能」（结合网络模块）

**跨模块答法**：网络分层排查（DNS/代理/证书）+ 把 `curl -v` 与客户端日志喂给 Agent 对比差异；限制 Agent 只改客户端网络栈相关路径。  
（详见 [network/web-protocols-interview/08-network-troubleshooting.md](../network/web-protocols-interview/08-network-troubleshooting.md)）

---

## 综合口述题

**Q：如果让你在团队落地 AI Coding，三个月怎么做？**

1. **月 1**：选点试点；Rules + CI 门禁；密钥红线；补全工具全员可用  
2. **月 2**：Agent 用于限定范围任务；建立 20 个回归任务集；Review 清单  
3. **月 3**：看指标（耗时、返工、事故）；决定是否扩大权限；补 Eval 与培训  

**Q：AI 写出「能跑但不正确」的并发代码，你怎么办？**

答：TSan/压力测红；Code Review 按 happens-before 讲清；Rules 写明 Qt 线程亲和；要求 Agent 先写并发测试再改实现；不接受「加锁扩大化」糊弄。

## 场景速查表

| 场景 | 关键动作 |
|------|----------|
| Bug | 原文日志 + 最小复现 + 测绿 |
| 跑题 | 白名单路径 + Reject |
| 新功能 | 先计划与测试后实现 |
| Review | 同人标准 + 更疑漂亮代码 |
| 重构 | 先锁行为 |
| 性能 | 先 profile |
| 机密 | 私有化/脱敏/权限 |
| 空转 | 熔断换策略 |
| 迁移 | 官方文档 + 编译驱动 |
