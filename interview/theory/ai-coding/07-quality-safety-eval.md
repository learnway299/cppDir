# 07 - 质量、安全与评测

## 核心概念

AI 编程的工程底线：**生成便宜，错误昂贵**。质量靠验收闭环，安全靠权限与数据边界，评测把「感觉变好」变成可回归的信号。

```
生成 → 自动检查（编译/测试/lint/秘钥扫描）→ 人工 Review → 合并
              ↑                                │
              └──────── 失败反馈给 Agent ───────┘
```

---

## 质量：如何验收 AI 产出

### 硬验收（优先）

| 门禁 | 作用 |
|------|------|
| 编译 / 类型检查 | 挡掉大量幻觉 API |
| 单元测试 / 属性测试 | 锁行为 |
| Sanitizers（ASan/TSan/UBSan） | C/C++ 内存与并发雷 |
| clang-tidy / 静态分析 | 风格与部分缺陷 |
| 快照 / 契约测试 | 防意外破坏 API |

### 软验收（必要但不充分）

- Diff 可读、改动面符合 issue  
- 无无关格式化大爆炸  
- 日志与错误处理符合项目惯例  
- 性能敏感路径有基本论证或基准  

### Definition of Done（给人或给 Agent）

写进任务描述，例如：

1. 复现用例由红变绿  
2. 新测覆盖失败路径  
3. 不修改 `third_party/`  
4. 文档若行为变更则同步

## 安全与合规

### 数据出域

| 风险 | 缓解 |
|------|------|
| 源码进公有云模型 | 企业合约、私有化、本地模型、目录忽略 |
| `.env` / 密钥进上下文 | 密钥扫描、忽略规则、红线提示 |
| 客户隐私日志 | 脱敏后再喂 Agent |
| Prompt 注入导致外泄 | 工具鉴权、禁止任意网络、审批 |

### 权限模型

- **只读模式**：分析、Review、讲解  
- **工作区写入**：默认可改业务代码  
- **命令执行**：分白名单（`ctest`）与高危确认（`git push`、生产脚本）  
- **网络**：默认关或仅允许包管理域名  

### 供应链

AI 建议的依赖可能是 **依赖混淆 / 恶意包名幻觉**。验收：官方源、锁版本、SBOM、最小新增依赖原则。

### 许可证与版权

- 输出可能类似已知开源代码：商业项目需策略与人工审查敏感片段  
- 训练数据争议属法律/政策层：工程师侧做到「可追溯生成、可 Review」

## 评测（Eval）

### 为什么要 Eval？

模型与提示词一变，Agent「突然变笨/变莽」。没有回归集就只能靠感觉。

### 评测金字塔（工程实用）

| 层 | 内容 | 频率 |
|----|------|------|
| 单元级 | 给定失败测试，Agent 能否在 N 步内修绿 | 每次改 Rules/工具 |
| 任务级 | 固定 issue 集（修 bug、加小功能）成功率 | 周/版本 |
| 轨迹级 | 是否乱改文件、是否乱执行命令 | 抽样 |
| 线上 | 返工率、回滚、事故 | 持续 |

开源/商业辅助：prompt 回归工具、轨迹 tracing；但 **仓库真实测试仍是金标准**。

### Guardrails（护栏）

- 输出过滤（秘钥正则）  
- 工具参数校验（路径必须在 repo 内）  
- 步数与费用熔断  
- 强制测试命令在「声明完成」前执行

## C++ / 客户端场景加分项

| 风险点 | AI 常见翻车 | 门禁 |
|--------|-------------|------|
| 所有权/生命周期 | 悬空引用叙事合理但错误 | ASan + Code Review |
| 并发 | 看起来同步的代码有竞态 | TSan、线程标注 |
| ABI / 跨 DLL | 乱改导出或布局 | 兼容性测试 |
| Qt 线程 | 在非 UI 线程碰控件 | 运行时断言、文档 Rules |
| UB | 未初始化、严格别名 | UBSan、经验清单 |

## 常见面试题

**Q1：如何给 AI 生成的 PR 做 Code Review？**  
答：先看意图与测试是否对齐；再看 Diff 是否最小；警惕无关重构；对安全与并发路径降级信任；要求 CI 全绿；高风险人工多盯一眼。

**Q2：怎样防止密钥被 AI 上传？**  
答：忽略规则 + pre-commit 扫描 + 环境变量不进仓库 + Agent 工具禁止读特定路径 + 企业 DLP/合约。

**Q3：没有评测集能不能上 Agent？**  
答：能小流量试用，但应用 **CI 门禁 + 人工 Review** 兜底；上规模前补最小任务集回归。

**Q4：Guardrails 和模型对齐的区别？**  
答：对齐偏训练/策略让模型「更愿意」安全；Guardrails 是系统层强制（就算模型想做也做不到）。工程上两者都要。

## 实战要点

- 「AI 写的」不是降质理由，也不是免审理由。  
- 先把 **测试命令写进 Rules**，再谈更强模型。  
- 事故复盘模板：上下文是否含密、工具是否过权、门禁是否可防。
