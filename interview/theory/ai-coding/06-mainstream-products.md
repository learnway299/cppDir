# 06 - 主流编程 AI 产品介绍

## 核心概念

按 **产品形态** 理解，而不是背功能列表：

| 形态 | 特征 | 代表方向 |
|------|------|----------|
| 行内补全 | 低延迟，续写当前光标 | Copilot 补全、各 Tab 补全 |
| Chat / 编辑器侧栏 | 选区解释、局部改写 | 多数 IDE 插件 |
| Agent（仓库级） | 多文件、工具、终端、多步任务 | Cursor Agent、Claude Code、Codex 类 |
| 补全 + Agent 一体 | 同一产品内切换模式 | Cursor、Windsurf 等 |

> 产品迭代极快；面试答 **定位与权衡**，并声明「以当时产品为准」。

---

## 横向对比维度

评估任何编程 AI，可用同一张表：

| 维度 | 要问什么 |
|------|----------|
| 核心范式 | 补全为主还是 Agent 为主 |
| 上下文 | 能吃多少仓库信号（打开文件、索引、规则） |
| 工具能力 | 是否读写文件、跑命令、浏览、MCP |
| 权限模型 | 默认自动执行还是逐步批准 |
| 模型选择 | 锁定一家还是可选多模型 |
| 部署与合规 | 纯云、企业专区、可否本地/私有 |
| 工作流 | Diff UX、PR 集成、后台任务 |
| 定价 | 按补全/请求/「agent 用量」 |

## 主流产品速览（中立）

### GitHub Copilot

- **强项**：IDE 内补全成熟、与 GitHub 生态（PR、Coding Agent 方向）结合紧  
- **典型用法**：日常敲代码加速、注释生成、简单 Chat  
- **注意**：仓库级自治能力因套餐/产品形态而异，面试区分「补全 Copilot」与「Agent 能力」

### Cursor

- **强项**：AI-native IDE；规则系统、仓库对话、Agent 多文件改动体验完整  
- **典型用法**：功能开发、重构辅助、带着 Rules 的团队约定  
- **注意**：云端上下文与权限策略需按公司合规配置

### Claude（含 Claude Code 等形态）

- **强项**：长上下文与工程推理口碑；CLI/Agent 向工作流适合「给任务让其在仓库里干活」  
- **典型用法**：复杂解释、多文件改造、结对式排障  
- **注意**：与 Anthropic API/订阅体系相关；权限与网络策略要单独评估

### OpenAI Codex / ChatGPT 编程能力

- **强项**：Codex 品牌强调软件工程 Agent；ChatGPT 覆盖广、工具生态多  
- **典型用法**：从自然语言到补丁、与 OpenAI 工具链集成  
- **注意**：同品牌下 Chat / API / IDE 扩展能力不同，回答时指明形态

### Windsurf 等 AI IDE

- **强项**：强调 Flow/Agent 连贯编辑体验（竞品定位接近 Cursor 类）  
- **典型用法**：深度编辑器内代理式编程  
- **注意**：面试用对比维度表，避免「谁绝对第一」

### Amazon Q / Tabnine / 其他

- **Amazon Q**：云厂商向，和企业 AWS 身份/知识源整合是卖点  
- **Tabnine 等**：常打「企业部署、代码不出域」合规牌  
- **JetBrains AI / VS Code 续写插件**：嵌在既有 IDE 习惯中

## 怎么选（场景决策）

| 场景 | 更合适的方向 |
|------|----------------|
| 日复一日写样板/补全 | 强补全产品即可 |
| 跨多文件特性 + 要跑测试 | Agent 型 IDE/CLI |
| 代码严禁出域 | 本地模型 / 企业私有化方案 |
| 已重度绑定 GitHub PR | Copilot + GitHub 工作流 |
| 已有强模型偏好（某家 API） | 可选模型的 Agent 宿主 |
| 终端/SSH 远程开发为主 | CLI Agent |

**互补用法（常见）**：补全管手感，Agent 管阶段性任务；CI 与 Review 管质量。

## 常见面试题

**Q1：Copilot 和 Cursor 有什么区别？**  
答：Copilot 起家于补全与 GitHub 集成；Cursor 是 AI 优先的 IDE，强调仓库级对话、规则与 Agent 工作流。二者都在向 Agent 演进，用「补全 vs 仓库 Agent」「宿主是插件还是独立 IDE」区分最稳。

**Q2：为什么还需要人？这些产品不能取代工程师吗？**  
答：需求澄清、架构权衡、责任与合规、不可测的领域约束仍在人侧；产品加速的是实现与探索，不是所有权与最终责任。

**Q3：选模型还是选产品？**  
答：产品 = 上下文采集 + 工具 + UX + 权限；模型 = 推理质量。同样模型在不同宿主里效果可差一截（索引与工具差异）。

**Q4：如何向领导证明值不值得买？**  
答：定指标：同类任务耗时、PR 返工率、线上缺陷、密钥事故零容忍；做小范围 A/B，而不是观感。

---

## 实战要点

- 团队统一：**规则文件 + Review 清单 + CI**，比争论品牌重要。  
- 开通 Agent 权限前先定红线（生产凭证、强制 push）。  
- 回答时效性问题时加半句：「具体功能以官网当前版为准」。
