# 09 - 浏览器导航全过程 (Browser Navigation)

## 简介

当用户在浏览器地址栏输入 URL 并按下回车，到页面完整显示，涉及网络、操作系统、浏览器渲染等多个层面。这是面试高频考点。

---

```
用户输入 URL 并按下回车
```

## 2. URL 解析

### 2.1 URL 结构

```
https://www.example.com:443/path/page.html?query=1&name=test#section1
   │          │          │        │              │             │
   │          │          │        │              │             └── 片段标识符
   │          │          │        │              └── 查询字符串
   │          │          │        └── 路径
   │          │          └── 端口（HTTPS 默认 443）
   │          └── 主机名（域名）
   └── 协议

URL 编码：
- 特殊字符需要 percent-encoding
- 空格 → %20
- 中文 → UTF-8 编码后 %XX%XX%XX
```

### 2.2 浏览器缓存检查

```
缓存检查顺序：

┌─────────────────────────────────────────────────────────────┐
│ 1. Service Worker 缓存                                      │
│    - PWA 应用的离线缓存                                     │
│    - 可编程的缓存策略                                       │
├─────────────────────────────────────────────────────────────┤
│ 2. Memory Cache（内存缓存）                                 │
│    - 当前 Tab 页面的资源缓存                                │
│    - 页面关闭即失效                                         │
│    - 响应最快                                               │
├─────────────────────────────────────────────────────────────┤
│ 3. Disk Cache（磁盘缓存）                                   │
│    - 持久化存储                                             │
│    - 根据 Cache-Control 判断                                │
│    - 容量大，速度较慢                                       │
├─────────────────────────────────────────────────────────────┤
│ 4. Push Cache（推送缓存）                                   │
│    - HTTP/2 Server Push 的资源                              │
│    - 会话级别，连接关闭即失效                               │
└─────────────────────────────────────────────────────────────┘

缓存命中判断：
- 强缓存：检查 Cache-Control / Expires
- 协商缓存：发请求验证 ETag / Last-Modified
```

## 4. TCP 连接建立

### 4.1 三次握手

```
TCP 三次握手：

客户端                                     服务器
   │                                          │
   │  ─── SYN, seq=x ───────────────────────► │
   │      状态：SYN_SENT                      │  状态：LISTEN → SYN_RCVD
   │                                          │
   │  ◄── SYN+ACK, seq=y, ack=x+1 ─────────── │
   │      状态：ESTABLISHED                   │
   │                                          │
   │  ─── ACK, seq=x+1, ack=y+1 ────────────► │
   │                                          │  状态：ESTABLISHED
   │  ════════ 连接建立，开始传输 ═══════════ │

耗时：1.5 RTT（Round-Trip Time）
```

### 4.2 TLS 握手（HTTPS）

```
TLS 1.2 握手（在 TCP 连接之后）：

客户端                                     服务器
   │                                          │
   │  ─── ClientHello ──────────────────────► │
   │      支持的密码套件、随机数               │
   │                                          │
   │  ◄── ServerHello ────────────────────── │
   │      选定的密码套件、随机数               │
   │  ◄── Certificate ─────────────────────── │
   │      服务器证书                          │
   │  ◄── ServerKeyExchange ─────────────── │
   │      ECDHE 参数                          │
   │  ◄── ServerHelloDone ─────────────────── │
   │                                          │
   │  ─── ClientKeyExchange ────────────────► │
   │      客户端 ECDHE 公钥                   │
   │  ─── ChangeCipherSpec ─────────────────► │
   │  ─── Finished ─────────────────────────► │
   │                                          │
   │  ◄── ChangeCipherSpec ──────────────── │
   │  ◄── Finished ────────────────────────── │
   │                                          │
   │  ════════ 开始加密传输 ════════════════ │

TLS 1.2 耗时：2 RTT
TLS 1.3 耗时：1 RTT（首次），0 RTT（恢复）

总连接耗时（TCP + TLS 1.2）：
= 1.5 RTT (TCP) + 2 RTT (TLS) = 3.5 RTT
```

### 4.3 连接优化

```
HTTP Keep-Alive：
- 复用 TCP 连接，避免重复握手
- HTTP/1.1 默认开启

HTTP/2：
- 单一 TCP 连接多路复用
- 减少连接开销

TLS Session Resumption：
- Session ID：服务器保存会话状态
- Session Ticket：客户端保存加密的会话状态
- 恢复连接可省去完整握手

TCP Fast Open (TFO)：
- 首次连接获取 Cookie
- 后续连接 SYN 包即可携带数据
```

## 5. HTTP 请求与响应

### 5.1 请求报文

```
完整 HTTP 请求：

GET /index.html HTTP/1.1                        ← 请求行
Host: www.example.com                           ← 必需
User-Agent: Mozilla/5.0 (Windows NT 10.0; ...)  ← 浏览器标识
Accept: text/html,application/xhtml+xml,...      ← 接受的内容类型
Accept-Language: zh-CN,zh;q=0.9,en;q=0.8        ← 语言偏好
Accept-Encoding: gzip, deflate, br              ← 支持的压缩
Connection: keep-alive                          ← 保持连接
Cookie: sessionId=abc123; theme=dark            ← Cookie
Cache-Control: max-age=0                        ← 缓存控制
If-None-Match: "5f6a8c3d-1234"                  ← 协商缓存
                                                ← 空行
[请求体，GET 通常没有]
```

### 7.3 CSSOM 构建

```
CSS 解析过程：

body { font-size: 16px; }
div { color: blue; }
div.highlight { background: yellow; }

        ┌─────────────┐
        │   CSSOM     │
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │    body     │
        │ font-size:16│
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │    div      │
        │ color:blue  │
        │ font-size:16│ ← 继承
        └──────┬──────┘
               │
        ┌──────▼──────┐

        │ color:blue  │ ← 继承

CSS 是渲染阻塞资源：
- 必须完成 CSSOM 才能构建渲染树
- 建议 CSS 放在 <head> 中尽早加载
```

### 7.4 JavaScript 执行

```
JavaScript 加载策略：

1. 普通 <script>（阻塞）
┌────────────────────────────────────────────────────────┐
│ HTML 解析 ─── 暂停 ─── 下载 JS ─── 执行 JS ─── 继续解析 │
└────────────────────────────────────────────────────────┘

2. <script async>（异步下载，下载完立即执行）
┌────────────────────────────────────────────────────────┐
│ HTML 解析 ───────────────── 暂停 ── 执行 ── 继续       │
│            └── 下载 JS ────┘                           │
└────────────────────────────────────────────────────────┘
适用：独立脚本，如统计代码

3. <script defer>（异步下载，DOMContentLoaded 前执行）
┌────────────────────────────────────────────────────────┐
│ HTML 解析 ─────────────────────────────── 执行 JS      │
│            └── 下载 JS ──────────────────┘             │
└────────────────────────────────────────────────────────┘
适用：依赖 DOM 的脚本，按顺序执行

4. 动态创建 script
const script = document.createElement('script');
script.src = 'app.js';
document.body.appendChild(script);
```

### 7.5 布局与绘制

```
布局（Layout / Reflow）：
┌─────────────────────────────────────────────────────────────────────┐
│ 计算每个元素的精确位置和大小                                         │
│                                                                     │
│ 触发条件：                                                          │
│ - 首次渲染                                                          │
│ - 窗口大小改变                                                      │
│ - 元素尺寸改变                                                      │
│ - 内容改变（文字、图片加载）                                        │
│ - 添加/删除 DOM 元素                                                │
│ - 读取布局属性（offsetWidth、scrollTop 等）                         │
│                                                                     │
│ 优化：批量修改、使用 transform 替代位置改变                          │
└─────────────────────────────────────────────────────────────────────┘

绘制（Paint）：
┌─────────────────────────────────────────────────────────────────────┐
│ 填充像素，生成位图                                                   │
│                                                                     │
│ 触发条件：                                                          │
│ - 布局改变                                                          │
│ - 颜色、背景改变                                                    │
│ - visibility 改变                                                   │
│                                                                     │
│ 层级：按 z-index 分层绘制                                           │
└─────────────────────────────────────────────────────────────────────┘

合成（Composite）：
┌─────────────────────────────────────────────────────────────────────┐
│ GPU 合成各层，生成最终画面                                          │
│                                                                     │
│ 独立合成层（只触发合成，不触发回流/重绘）：                          │
│ - transform                                                         │
│ - opacity                                                           │
│ - will-change                                                       │
│ - video、canvas、WebGL                                              │
│                                                                     │
│ 优化：使用 transform 和 opacity 做动画                              │
└─────────────────────────────────────────────────────────────────────┘
```

## 8. 关键性能指标

### 8.1 核心 Web Vitals

```
┌─────────────────────────────────────────────────────────────────────┐
│ LCP (Largest Contentful Paint) - 最大内容绘制                       │
│   含义：最大内容元素渲染完成的时间                                  │
│   目标：< 2.5 秒                                                    │
│   影响因素：服务器响应、CSS/JS 阻塞、资源加载                       │
├─────────────────────────────────────────────────────────────────────┤
│ FID (First Input Delay) - 首次输入延迟                              │
│   含义：用户首次交互到浏览器响应的时间                              │
│   目标：< 100 毫秒                                                  │
│   影响因素：主线程被 JS 占用                                        │
├─────────────────────────────────────────────────────────────────────┤
│ CLS (Cumulative Layout Shift) - 累积布局偏移                        │
│   含义：页面元素意外移动的程度                                      │
│   目标：< 0.1                                                       │
│   影响因素：图片无尺寸、动态内容、字体加载                          │
└─────────────────────────────────────────────────────────────────────┘
```

```
                               首字节到达时间

┌─────────────────────────────────────────────────────────────────────┐
│ TTFB (Time to First Byte)                                           │
│   请求发出到收到首字节                                              │
│   目标：< 200ms（CDN），< 600ms（动态）                              │
├─────────────────────────────────────────────────────────────────────┤
│ FCP (First Contentful Paint)                                        │
│   首次内容绘制（任何文字、图片）                                    │
│   目标：< 1.8 秒                                                    │
├─────────────────────────────────────────────────────────────────────┤
│ TTI (Time to Interactive)                                           │
│   页面完全可交互                                                    │
│   目标：< 3.8 秒                                                    │
├─────────────────────────────────────────────────────────────────────┤
│ DOMContentLoaded                                                    │
│   DOM 解析完成（不等待 CSS、图片）                                  │
├─────────────────────────────────────────────────────────────────────┤
│ Load                                                                │
│   所有资源加载完成                                                  │
└─────────────────────────────────────────────────────────────────────┘
```

## 9. 性能优化策略

### 9.1 网络层优化

```
DNS 优化：
- DNS 预解析：<link rel="dns-prefetch">
- 减少不同域名数量

连接优化：
- 使用 HTTP/2 或 HTTP/3
- 预连接：<link rel="preconnect">
- 启用 TLS 1.3

传输优化：
- 启用 Gzip/Brotli 压缩
- 使用 CDN
- 静态资源长期缓存
```

### 9.2 资源加载优化

```
关键资源优化：
<!-- 预加载关键资源 -->
<link rel="preload" href="critical.css" as="style">
<link rel="preload" href="main.js" as="script">
<link rel="preload" href="hero.jpg" as="image">

<!-- 预获取下一页资源 -->
<link rel="prefetch" href="page2.html">

JavaScript 优化：
- 代码分割（Code Splitting）
- 树摇（Tree Shaking）
- defer/async 加载
- 懒加载非首屏模块

图片优化：
- 响应式图片 srcset
- 懒加载 loading="lazy"
- 使用 WebP/AVIF 格式
- 图片 CDN 动态裁剪
```

### 9.3 渲染优化

```
CSS 优化：
- 关键 CSS 内联
- 非关键 CSS 异步加载
- 避免 @import
- 减少选择器复杂度

避免强制同步布局：
// 错误示例：读写交替触发多次回流
for (let i = 0; i < items.length; i++) {
    items[i].style.width = box.offsetWidth + 'px';  // 读
    items[i].style.height = '100px';                 // 写
}

// 正确示例：批量读，批量写
const width = box.offsetWidth;  // 读一次
for (let i = 0; i < items.length; i++) {
    items[i].style.width = width + 'px';   // 只写
    items[i].style.height = '100px';
}

动画优化：
- 使用 transform 和 opacity
- 使用 requestAnimationFrame
- 使用 will-change 提升层
```

## 10. 面试高频问题

**Q1：从输入 URL 到页面显示，经历了什么？**
```
简答版：
1. URL 解析，检查缓存
2. DNS 解析域名为 IP
3. TCP 三次握手建立连接
4. HTTPS 则进行 TLS 握手
5. 发送 HTTP 请求
6. 服务器处理返回响应
7. 浏览器解析 HTML 构建 DOM
8. 解析 CSS 构建 CSSOM
9. 合成渲染树，布局，绘制
10. JavaScript 执行
11. 页面完整显示

重点展开任意环节，如：
- DNS 多级缓存
- TCP 三次握手细节
- TLS 握手过程
- 渲染树构建
```

**Q2：为什么 CSS 要放 head，JS 要放 body 底部？**
```
CSS 放 head：
- CSS 是渲染阻塞资源
- 尽早下载，尽早构建 CSSOM
- 避免 FOUC（无样式内容闪烁）

JS 放 body 底部：
- JS 阻塞 HTML 解析
- DOM 构建完成后执行更安全
- 或使用 defer/async
```

**Q3：什么是回流和重绘？如何优化？**
```
回流（Reflow）：
- 元素几何属性改变，重新计算布局
- 代价高，触发重绘

重绘（Repaint）：
- 外观改变但不影响布局
- 代价较低

优化：
- 使用 transform 代替位置属性
- 批量 DOM 操作
- 使用 DocumentFragment
- 避免频繁读取布局属性
- 使用 will-change 创建合成层
```

**Q4：浏览器一帧内做了什么？**
```
60fps = 每帧 16.67ms

一帧内的工作：
1. 处理用户输入事件
2. JavaScript 执行
3. requestAnimationFrame
4. 计算样式（Style）
5. 布局（Layout）
6. 绘制（Paint）
7. 合成（Composite）

如果超过 16.67ms：
- 掉帧，动画卡顿
- 使用 Web Worker 分离计算
- 使用 requestIdleCallback 处理低优先级任务
```

**Q5：预加载和预获取的区别？**
```
preload：
- 当前页面需要的关键资源
- 高优先级下载
- 不使用会警告
- 例：首屏字体、关键 CSS

prefetch：
- 下一页可能需要的资源
- 低优先级，空闲时下载
- 不一定使用
- 例：下一页的 JS bundle

preconnect：
- 提前建立连接（DNS + TCP + TLS）
- 用于确定会访问的第三方域名
```

**Q6：HTTP/2 如何提升页面加载速度？**
```
1. 多路复用
   - 单连接并行请求
   - 无需域名分片
   - 减少连接开销

2. 头部压缩
   - HPACK 算法
   - 减少传输数据

3. 服务器推送
   - 主动推送 CSS/JS
   - 减少请求往返

4. 二进制分帧
   - 更高效解析
   - 支持优先级
```
