# C++ 智能指针面试专项

> 本文基于 `06-memory.md` 的智能指针章节整理，并补充双向持有、引用计数变化、生命周期设计等高频面试问答。

---

## 1. 为什么需要智能指针

**问题：为什么不直接用 `new/delete`？**

**回答：**
- 手写 `delete` 容易漏掉，导致内存泄漏。
- 异常路径和多返回路径容易遗漏释放。
- 所有权语义不清晰，团队协作容易误用。
- 智能指针遵循 RAII，离开作用域自动释放，异常安全更好。

---

## 2. `unique_ptr` 面试要点

**问题：`unique_ptr` 的核心特性是什么？**

**回答：**
- 独占所有权，不可拷贝，可移动。
- 零额外引用计数开销，默认首选。
- 适合“单一所有者”场景。

**问题：`new` + `unique_ptr` 与 `make_unique` 怎么选？**

**回答：**
- 优先 `make_unique`，写法更简洁、异常安全更好。
- 需要接管遗留裸指针或显式传入自定义删除器时可用 `new`。

```cpp
auto p1 = std::make_unique<int>(42);          // 推荐
std::unique_ptr<int> p2(new int(42));         // 可用，但默认不优先
```

---

## 3. `shared_ptr` 面试要点

**问题：`shared_ptr` 如何实现共享所有权？**

**回答：**
- 通过控制块（control block）维护强引用计数和弱引用计数。
- 强引用计数归零时析构托管对象。
- 弱计数也归零后释放控制块。

**问题：`shared_ptr` 引用计数什么时候增减？**

**回答：**
- 增加（`+1`）：
  - 拷贝构造、拷贝赋值。
  - 按值传参。
  - `weak_ptr.lock()` 成功得到新的 `shared_ptr`。
- 减少（`-1`）：
  - `shared_ptr` 析构离开作用域。
  - `reset()`。
  - 覆盖赋值为其他对象或 `nullptr`。
- `std::move(shared_ptr)` 仅转移所有权，不增加强计数。

---

## 4. `weak_ptr` 面试要点

**问题：`weak_ptr` 解决什么问题？**

**回答：**
- 解决 `shared_ptr` 循环引用。
- 表达“可访问但不拥有”的关系。
- 不增加强引用计数，不延长对象生命周期。

**问题：怎么安全使用 `weak_ptr`？**

**回答：**
- 先 `lock()`，拿到临时 `shared_ptr` 再访问对象。
- 不能直接解引用 `weak_ptr`。

```cpp
if (auto sp = wp.lock()) {
    sp->doWork();
}
```

## 5. 你刚问过的高频场景（补充）

### 5.1 `T*` / `T**` 有没有引用计数？

**回答：**
- 原生指针（包括二级指针 `T**`）本身没有引用计数机制。
- 引用计数是 `shared_ptr` 的机制，不是指针语法特性。

### 5.2 A/B 互相调用方法，谁用 `shared_ptr`，谁用 `weak_ptr`？

**回答：**
- 看“谁拥有谁”，不是看“谁调用谁”。
- 拥有方用强拥有（`unique_ptr` 或 `shared_ptr`）。
- 回指和观察方用 `weak_ptr`。
- 双向都用 `shared_ptr` 会形成环，导致泄漏。

### 5.3 根据什么判断用哪种指针类型？

**回答：**
1. 先定所有权：谁负责销毁。
2. 单一拥有者：`unique_ptr`。
3. 多方共同保活：`shared_ptr`。
4. 只访问不保活：`weak_ptr`（或引用/裸指针）。
5. 出现环时至少一条边改成 `weak_ptr`。

### 5.4 A/B 生命周期长短不一致，怎么持有？

**回答：**
- 短生命周期对象若依赖长生命周期对象且后者必定存活，可用引用/裸指针。
- 长生命周期对象指向可能先销毁的短生命周期对象，默认用 `weak_ptr`。
- 只有在业务上确实需要“保活”对方时，才用 `shared_ptr`。

### 5.5 `A a; B b;`（栈对象）互相指向要不要 `shared_ptr/weak_ptr`？

**回答：**
- 不要。栈对象生命周期由作用域管理，不应交给智能指针控制。
- 用 `A* / B*` 或引用表达关联关系即可。

## 6. 常见“原理类”面试题与解答

### 6.1 `shared_ptr` 控制块里通常有什么？

**回答：**
- 强引用计数（use count）。
- 弱引用计数（weak count）。
- 删除器（deleter）和分配器（allocator）相关信息。
- 指向托管对象或对象就地存储信息（`make_shared` 场景）。

### 6.2 为什么 `make_shared` 往往更高效？

**回答：**
- 通常一次分配同时放对象和控制块，减少分配次数与碎片。
- `shared_ptr<T>(new T)` 往往需要对象与控制块两次分配。

### 6.3 `make_shared` 有什么代价？

**回答：**
- 对象与控制块绑在同一块内存，最后一个 `weak_ptr` 消失前这块内存不能完全回收。
- 对大对象或生命周期差异明显场景，需要权衡。

### 6.4 `use_count()` 能用于并发逻辑判断吗？

**回答：**
- 不推荐作为并发判定依据。
- 它通常只用于调试观察，业务逻辑依赖它容易竞态。

### 6.5 `shared_ptr` 是线程安全吗？

**回答：**
- 对“同一控制块引用计数增减”是线程安全的。
- 对“被管理对象本身的读写”不是自动线程安全，仍需锁或无锁同步。

### 6.6 为什么不该从同一个裸指针构造多个 `shared_ptr`？

**回答：**
- 会形成多个控制块，各自认为自己拥有对象，最终 double free。

### 6.7 什么是 `enable_shared_from_this`？何时用？

**回答：**
- 让对象内部安全拿到“指向自身”的 `shared_ptr`，并复用同一个控制块。
- 典型场景：异步回调中延长自身生命周期。

### 6.8 自定义删除器常见用途是什么？

**回答：**
- 管理非 `new` 资源：`FILE*`、socket、句柄、第三方库对象等。
- `unique_ptr` 更常见，`shared_ptr` 也支持。

## 7. 常见“应用类”面试题与解答

### 7.1 观察者模式该怎么选智能指针？

**回答：**
- Subject 通常强持有 Observer 容器。
- Observer 回指 Subject 常用 `weak_ptr`，避免环。

### 7.2 缓存系统里为什么常见 `weak_ptr`？

**回答：**
- 缓存可存 `weak_ptr` 避免“缓存条目意外保活对象”。
- 命中后 `lock()`，失败表示对象已释放。

### 7.3 接口返回值用什么？

**回答：**
- 默认返回值对象或 `unique_ptr`（表达转移所有权）。
- 需要共享生命周期再返回 `shared_ptr`。
- 不要“为了方便”一律 `shared_ptr`。

### 7.4 容器里放裸指针还是智能指针？

**回答：**
- 有所有权放 `unique_ptr/shared_ptr`。
- 无所有权可放裸指针，但要明确上游生命周期并做好文档约束。

### 7.5 双向图结构（节点互指）怎么避免泄漏？

**回答：**
- 只保留一个方向为强拥有，反向边用 `weak_ptr`。
- 或由外部 Graph/Manager 统一强持有所有节点，节点间用 `weak_ptr`。

---

## 8. 一页速记（面试快答）

- 默认：`unique_ptr`。  
- 共享保活：`shared_ptr`。  
- 观察/回指/断环：`weak_ptr`。  
- 有环必断：至少一条边 `weak_ptr`。  
- `shared_ptr` 计数加减：拷贝加、析构/reset/覆盖减、move 不加。  
- 栈对象不交给智能指针托管。  
- 不要从同一裸指针构造多个 `shared_ptr`。  
- `make_unique`/`make_shared` 通常优先于直接 `new`。
