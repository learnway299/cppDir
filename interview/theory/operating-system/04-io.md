# 04 - I/O 系统 (I/O System)

## 简介

I/O 系统是操作系统与外部设备交互的核心，理解不同的 I/O 模型对于编写高性能网络程序至关重要。

**核心概念**：
- **同步/异步**：关注消息通知机制
- **阻塞/非阻塞**：关注等待结果时的状态
- **I/O 多路复用**：单线程监控多个文件描述符
- **select/poll/epoll**：Linux I/O 多路复用实现

---

## 1. I/O 基础概念

### 1.1 同步与异步

**面试问题**：同步 I/O 和异步 I/O 有什么区别？

**答案**：

| 特性 | 同步 (Synchronous) | 异步 (Asynchronous) |
|------|-------------------|---------------------|
| **定义** | 调用方等待操作完成 | 调用方不等待，通过回调/信号通知 |
| **数据拷贝** | 调用方负责 | 内核负责 |
| **编程模型** | 顺序执行 | 事件驱动 |

```
同步 I/O：

应用程序                    内核
    │                        │
    │─── read() ────────────►│
    │                        │ 等待数据
    │      (阻塞等待)        │ 复制数据
    │◄──── 返回数据 ─────────│
    │                        │


异步 I/O：

应用程序                    内核
    │                        │
    │─── aio_read() ────────►│
    │◄── 立即返回 ───────────│
    │                        │ 等待数据
    │   (继续其他工作)       │ 复制数据
    │◄── 信号/回调通知 ──────│
    │                        │
```

---

### 1.2 阻塞与非阻塞

**面试问题**：阻塞和非阻塞有什么区别？

**答案**：

| 特性 | 阻塞 (Blocking) | 非阻塞 (Non-blocking) |
|------|-----------------|----------------------|
| **定义** | 数据未就绪时挂起进程 | 立即返回（可能返回错误） |
| **等待** | 进程/线程阻塞 | 需要轮询检查 |
| **CPU 使用** | 低（挂起不占用） | 高（需要轮询） |

```
阻塞 I/O：

应用程序                    内核
    │                        │
    │─── read() ────────────►│
    │                        │
    │   (进程睡眠)           │ 数据未就绪
    │                        │
    │                        │ 数据到达
    │                        │ 复制到用户空间
    │◄──── 返回数据 ─────────│
    │                        │


非阻塞 I/O：

应用程序                    内核
    │                        │
    │─── read() ────────────►│
    │◄── EAGAIN ─────────────│ 数据未就绪
    │                        │
    │─── read() ────────────►│
    │◄── EAGAIN ─────────────│ 数据未就绪
    │                        │
    │─── read() ────────────►│
    │◄── 返回数据 ───────────│ 数据就绪
    │                        │
```

---

### 1.3 同步/异步 与 阻塞/非阻塞 的关系

**面试问题**：同步/异步和阻塞/非阻塞是什么关系？

**答案**：

```
┌─────────────────┬─────────────────┬─────────────────┐
│                 │     阻塞         │     非阻塞      │
├─────────────────┼─────────────────┼─────────────────┤
│     同步        │ 同步阻塞 I/O     │ 同步非阻塞 I/O  │
│                 │ (普通 read)      │ (轮询)          │
├─────────────────┼─────────────────┼─────────────────┤
│     异步        │ 异步阻塞         │ 异步非阻塞 I/O  │
│                 │ (很少见)         │ (aio_read)      │
└─────────────────┴─────────────────┴─────────────────┘

关键区别：
- 同步/异步：关注数据拷贝由谁完成
- 阻塞/非阻塞：关注等待数据时进程状态
```

## 2. Unix 五种 I/O 模型

### 2.1 五种模型概述

**面试问题**：Unix 有哪五种 I/O 模型？

**答案**：

#### 1. 阻塞 I/O (Blocking I/O)

```c
// 最简单的模型
int fd = socket(AF_INET, SOCK_STREAM, 0);
char buf[1024];

// 阻塞等待数据
ssize_t n = read(fd, buf, sizeof(buf));  // 进程阻塞直到数据到达
```

```
应用程序                    内核
    │                        │
    │─── recvfrom() ────────►│
    │                        │ 等待数据
    │   ┌──────────────────┐ │
    │   │   进程阻塞       │ │
    │   └──────────────────┘ │
    │                        │ 数据到达
    │                        │ 复制数据
    │◄── 返回数据 ───────────│
    │                        │
```

#### 2. 非阻塞 I/O (Non-blocking I/O)

```c
// 设置非阻塞
int flags = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, flags | O_NONBLOCK);

// 轮询检查
while (1) {
    ssize_t n = read(fd, buf, sizeof(buf));
    if (n > 0) {
        // 有数据
        break;
    } else if (n == -1 && errno == EAGAIN) {
        // 暂无数据，继续轮询
        continue;
    }
}
```

```
应用程序                    内核
    │                        │
    │─── recvfrom() ────────►│
    │◄── EAGAIN ─────────────│ 无数据
    │─── recvfrom() ────────►│
    │◄── EAGAIN ─────────────│ 无数据
    │─── recvfrom() ────────►│
    │◄── EAGAIN ─────────────│ 无数据
    │─── recvfrom() ────────►│
    │                        │ 数据到达
    │                        │ 复制数据
    │◄── 返回数据 ───────────│
    │                        │
```

#### 3. I/O 多路复用 (I/O Multiplexing)

```c
fd_set readfds;
FD_ZERO(&readfds);
FD_SET(fd1, &readfds);
FD_SET(fd2, &readfds);

// 阻塞等待任一 fd 就绪
int ret = select(maxfd + 1, &readfds, NULL, NULL, NULL);

if (FD_ISSET(fd1, &readfds)) {
    read(fd1, buf, sizeof(buf));
}
```

```
应用程序                    内核
    │                        │
    │─── select() ──────────►│
    │                        │
    │   ┌──────────────────┐ │ 监控多个 fd
    │   │   进程阻塞       │ │
    │   └──────────────────┘ │
    │                        │ 某个 fd 就绪
    │◄── 返回就绪 fd ────────│
    │                        │
    │─── recvfrom() ────────►│
    │◄── 返回数据 ───────────│
    │                        │
```

#### 4. 信号驱动 I/O (Signal-driven I/O)

```c
// 设置信号处理
void sigio_handler(int sig) {
    // 数据就绪，可以读取
}
signal(SIGIO, sigio_handler);

// 设置异步通知
fcntl(fd, F_SETOWN, getpid());
int flags = fcntl(fd, F_GETFL);
fcntl(fd, F_SETFL, flags | O_ASYNC);

// 继续其他工作，收到 SIGIO 时处理数据
```

```
应用程序                    内核
    │                        │
    │─── sigaction() ───────►│ 注册 SIGIO 处理
    │◄── 返回 ───────────────│
    │                        │
    │   (继续其他工作)       │ 等待数据
    │                        │
    │◄── SIGIO 信号 ─────────│ 数据就绪
    │                        │
    │─── recvfrom() ────────►│
    │◄── 返回数据 ───────────│
    │                        │
```

#### 5. 异步 I/O (Asynchronous I/O)

```c
#include <aio.h>

struct aiocb cb;
memset(&cb, 0, sizeof(cb));
cb.aio_fildes = fd;
cb.aio_buf = buf;
cb.aio_nbytes = sizeof(buf);
cb.aio_sigevent.sigev_notify = SIGEV_SIGNAL;
cb.aio_sigevent.sigev_signo = SIGUSR1;

// 发起异步读取
aio_read(&cb);

// 继续其他工作...

// 信号处理函数中处理完成事件
void sigusr1_handler(int sig) {
    if (aio_error(&cb) == 0) {
        ssize_t n = aio_return(&cb);
        // 处理数据
    }
}
```

```
应用程序                    内核
    │                        │
    │─── aio_read() ────────►│
    │◄── 立即返回 ───────────│
    │                        │
    │   (继续其他工作)       │ 等待数据
    │                        │ 数据到达
    │                        │ 复制到用户缓冲区
    │◄── 信号通知完成 ───────│
    │                        │
```

### 2.2 五种模型对比

```
                阻塞 I/O     非阻塞 I/O    I/O 多路复用   信号驱动     异步 I/O
                  │            │              │            │            │
发起请求 ─────────┼────────────┼──────────────┼────────────┼────────────┤
                  │            │              │            │            │
                  │ 阻塞       │ 轮询          │ 阻塞       │            │
                  │            │              │            │            │
等待数据          │            │              │            │  继续工作   │ 继续工作
                  │            │              │            │            │
                  │            │              │            │            │
数据就绪 ─────────┼────────────┼──────────────┼────────────┼────────────┤
                  │ 复制数据   │ 复制数据     │ 复制数据   │ 复制数据   │
                  │ (同步)     │ (同步)       │ (同步)     │ (同步)     │ (内核完成)
                  │            │              │            │            │
返回结果 ─────────┼────────────┼──────────────┼────────────┼────────────┤
                  ▼            ▼              ▼            ▼            ▼

前四种都是同步 I/O（应用程序负责数据拷贝）
只有异步 I/O 是真正的异步（内核完成数据拷贝）
```

| 模型 | 阻塞等待 | 轮询 | 适用场景 |
|------|----------|------|----------|
| 阻塞 I/O | 是 | 否 | 简单场景 |
| 非阻塞 I/O | 否 | 是 | CPU 密集型 |
| I/O 多路复用 | 是 | 否 | 高并发服务器 |
| 信号驱动 | 否 | 否 | 实时性要求高 |
| 异步 I/O | 否 | 否 | 高性能场景 |

## 3. I/O 多路复用详解

### 3.1 select

**面试问题**：select 的原理是什么？有什么限制？

**答案**：

```c
#include <sys/select.h>

int select(int nfds, fd_set *readfds, fd_set *writefds,
           fd_set *exceptfds, struct timeval *timeout);

// fd_set 操作宏
FD_ZERO(&set);      // 清空集合
FD_SET(fd, &set);   // 添加 fd
FD_CLR(fd, &set);   // 移除 fd
FD_ISSET(fd, &set); // 检查 fd 是否在集合中
```

**使用示例**：

```c
#include <sys/select.h>
#include <unistd.h>
#include <stdio.h>

void select_example() {
    fd_set readfds;
    int sockfd1 = 3, sockfd2 = 4;  // 假设的 socket fd
    int maxfd = sockfd2;

    while (1) {
        FD_ZERO(&readfds);
        FD_SET(sockfd1, &readfds);
        FD_SET(sockfd2, &readfds);

        // 超时设置
        struct timeval timeout;
        timeout.tv_sec = 5;
        timeout.tv_usec = 0;

        int ret = select(maxfd + 1, &readfds, NULL, NULL, &timeout);

        if (ret < 0) {
            perror("select");
            break;
        } else if (ret == 0) {
            printf("timeout\n");
            continue;
        }

        if (FD_ISSET(sockfd1, &readfds)) {
            // sockfd1 可读
            char buf[1024];
            read(sockfd1, buf, sizeof(buf));
        }
        if (FD_ISSET(sockfd2, &readfds)) {
            // sockfd2 可读
            char buf[1024];
            read(sockfd2, buf, sizeof(buf));
        }
    }
}
```

**select 的限制**：

| 限制 | 说明 |
|------|------|
| fd 数量限制 | FD_SETSIZE (通常 1024) |
| 每次调用需重新设置 | fd_set 被内核修改 |
| 线性扫描 | O(n) 检查每个 fd |
| 数据拷贝 | 每次调用拷贝 fd_set 到内核 |

### 3.2 poll

**面试问题**：poll 相比 select 有什么改进？

**答案**：

```c
#include <poll.h>

int poll(struct pollfd *fds, nfds_t nfds, int timeout);

struct pollfd {
    int   fd;       // 文件描述符
    short events;   // 关注的事件
    short revents;  // 实际发生的事件
};
```

**使用示例**：

```c
#include <poll.h>
#include <unistd.h>
#include <stdio.h>

void poll_example() {
    struct pollfd fds[2];

    fds[0].fd = 3;  // sockfd1
    fds[0].events = POLLIN;

    fds[1].fd = 4;  // sockfd2
    fds[1].events = POLLIN;

    while (1) {
        int ret = poll(fds, 2, 5000);  // 5 秒超时

        if (ret < 0) {
            perror("poll");
            break;
        } else if (ret == 0) {
            printf("timeout\n");
            continue;
        }

        for (int i = 0; i < 2; i++) {
            if (fds[i].revents & POLLIN) {
                char buf[1024];
                read(fds[i].fd, buf, sizeof(buf));
            }
        }
    }
}
```

**poll 事件类型**：

| 事件 | 说明 |
|------|------|
| `POLLIN` | 有数据可读 |
| `POLLOUT` | 可以写入 |
| `POLLERR` | 发生错误 |
| `POLLHUP` | 对端挂断 |
| `POLLNVAL` | 无效的 fd |

**poll vs select**：

| 特性 | select | poll |
|------|--------|------|
| fd 数量限制 | 1024 | 无限制（数组） |
| 接口 | fd_set 位图 | pollfd 数组 |
| 重设 | 每次需重设 | 只需检查 revents |
| 效率 | O(n) | O(n) |

### 3.3 epoll

**面试问题**：epoll 的原理是什么？为什么比 select/poll 高效？

**答案**：

```c
#include <sys/epoll.h>

// 创建 epoll 实例
int epoll_create(int size);      // size 被忽略，但需 > 0
int epoll_create1(int flags);    // 推荐使用

// 控制 epoll 实例
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
// op: EPOLL_CTL_ADD, EPOLL_CTL_MOD, EPOLL_CTL_DEL

// 等待事件
int epoll_wait(int epfd, struct epoll_event *events,
               int maxevents, int timeout);

struct epoll_event {
    uint32_t events;   // 事件类型
    epoll_data_t data; // 用户数据
};
```

**使用示例**：

```c
#include <sys/epoll.h>
#include <unistd.h>
#include <stdio.h>

#define MAX_EVENTS 10

void epoll_example(int listenfd) {
    int epfd = epoll_create1(0);

    // 添加监听 socket
    struct epoll_event ev;
    ev.events = EPOLLIN;
    ev.data.fd = listenfd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, listenfd, &ev);

    struct epoll_event events[MAX_EVENTS];

    while (1) {
        int nfds = epoll_wait(epfd, events, MAX_EVENTS, -1);

        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == listenfd) {
                // 新连接
                int clientfd = accept(listenfd, NULL, NULL);
                ev.events = EPOLLIN | EPOLLET;  // 边缘触发
                ev.data.fd = clientfd;
                epoll_ctl(epfd, EPOLL_CTL_ADD, clientfd, &ev);
            } else {
                // 客户端数据
                char buf[1024];
                read(events[i].data.fd, buf, sizeof(buf));
            }
        }
    }

    close(epfd);
}
```

**epoll 事件类型**：

| 事件 | 说明 |
|------|------|
| `EPOLLIN` | 有数据可读 |
| `EPOLLOUT` | 可以写入 |
| `EPOLLERR` | 发生错误 |
| `EPOLLHUP` | 对端挂断 |
| `EPOLLET` | 边缘触发模式 |
| `EPOLLONESHOT` | 只触发一次 |

### 3.4 epoll 的两种触发模式

**面试问题**：epoll 的水平触发和边缘触发有什么区别？

**答案**：

```
水平触发 (Level Triggered, LT)：
- 默认模式
- 只要缓冲区有数据，就持续通知
- 类似 select/poll 的行为

边缘触发 (Edge Triggered, ET)：
- 需要显式设置 EPOLLET
- 只在状态变化时通知一次
- 必须一次性读完所有数据
- 效率更高，但编程更复杂
```

```
示例：缓冲区有 10 字节数据

水平触发 (LT)：
epoll_wait() → 返回可读 → read(5 字节)
epoll_wait() → 返回可读 → read(5 字节)  // 还有数据，继续通知
epoll_wait() → 阻塞（无数据）

边缘触发 (ET)：
epoll_wait() → 返回可读 → read(5 字节)
epoll_wait() → 阻塞！  // 状态没变化，不会再通知
              // 剩余 5 字节数据被"遗忘"
```

**边缘触发的正确使用**：

```c
// ET 模式必须：
// 1. 设置非阻塞
// 2. 循环读取直到 EAGAIN

void handle_et_read(int fd) {
    char buf[1024];

    while (1) {
        ssize_t n = read(fd, buf, sizeof(buf));

        if (n > 0) {
            // 处理数据
        } else if (n == 0) {
            // 连接关闭
            close(fd);
            break;
        } else {
            if (errno == EAGAIN || errno == EWOULDBLOCK) {
                // 数据读完
                break;
            }
            // 其他错误
            perror("read");
            break;
        }
    }
}
```

### 3.5 select/poll/epoll 对比

**面试问题**：select、poll、epoll 的区别是什么？

**答案**：

| 特性 | select | poll | epoll |
|------|--------|------|-------|
| **数据结构** | 位图 | 数组 | 红黑树 + 链表 |
| **fd 数量限制** | 1024 | 无限制 | 无限制 |
| **fd 拷贝** | 每次全量拷贝 | 每次全量拷贝 | 仅注册时拷贝 |
| **时间复杂度** | O(n) | O(n) | O(1) |
| **触发模式** | 水平触发 | 水平触发 | 水平/边缘触发 |
| **适用场景** | fd 少、跨平台 | fd 少 | Linux 高并发 |

**epoll 为什么高效**：

```
select/poll：
┌─────────────────────────────────────────────────────────┐
│  每次调用：                                             │
│  1. 拷贝所有 fd 到内核                                  │
│  2. 内核遍历所有 fd，检查状态                           │
│  3. 返回后，应用程序遍历检查哪些 fd 就绪               │
│                                                         │
│  时间复杂度：O(n)                                       │
└─────────────────────────────────────────────────────────┘

epoll：
┌─────────────────────────────────────────────────────────┐
│  epoll_create：创建 epoll 实例                         │
│                                                         │
│  epoll_ctl：                                            │
│  - 将 fd 添加到红黑树                                   │
│  - 设置回调函数                                         │
│                                                         │
│  事件发生时：                                           │
│  - 回调函数将就绪 fd 加入链表                           │
│                                                         │
│  epoll_wait：                                           │
│  - 检查就绪链表（不需要遍历所有 fd）                    │
│  - 只返回就绪的 fd                                      │
│                                                         │
│  时间复杂度：O(就绪 fd 数量)                            │
└─────────────────────────────────────────────────────────┘
```

**epoll 内部结构**：

```
┌─────────────────────────────────────────────────────────┐
│                    epoll 实例                           │
│                                                         │
│  ┌───────────────────────────────────────────────────┐ │
│  │                 红黑树                             │ │
│  │        存储所有注册的 fd                          │ │
│  │                                                   │ │
│  │              ┌───┐                                │ │
│  │              │   │                                │ │
│  │         ┌────┴───┴────┐                          │ │
│  │         │             │                          │ │
│  │      ┌──┴──┐       ┌──┴──┐                       │ │
│  │      │fd:3 │       │fd:7 │                       │ │
│  │      └─────┘       └─────┘                       │ │
│  └───────────────────────────────────────────────────┘ │
│                                                         │
│  ┌───────────────────────────────────────────────────┐ │
│  │                就绪链表                            │ │
│  │        存储有事件发生的 fd                        │ │
│  │                                                   │ │
│  │   [fd:3] ──► [fd:5] ──► [fd:12] ──► NULL          │ │
│  │                                                   │ │
│  └───────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

## 4. Reactor 与 Proactor 模式

### 4.1 Reactor 模式

**面试问题**：什么是 Reactor 模式？

**答案**：

**Reactor（反应器）模式**：基于事件驱动，主线程负责监听事件，将就绪的事件分发给工作线程处理。

```
                    ┌─────────────────────────────────────┐
                    │           Reactor                   │
                    │                                     │
   ┌────────────┐   │   ┌─────────────────────────────┐  │
   │  Client 1  │◄──┼───│      Event Demultiplexer    │  │
   └────────────┘   │   │      (epoll/select/poll)    │  │
                    │   └──────────────┬──────────────┘  │
   ┌────────────┐   │                  │                 │
   │  Client 2  │◄──┤                  │                 │
   └────────────┘   │                  ▼                 │
                    │   ┌─────────────────────────────┐  │
   ┌────────────┐   │   │       Dispatcher            │  │
   │  Client 3  │◄──┤   │       事件分发器            │  │
   └────────────┘   │   └──────────────┬──────────────┘  │
                    │                  │                 │
                    │         ┌────────┼────────┐        │
                    │         ▼        ▼        ▼        │
                    │   ┌────────┐┌────────┐┌────────┐   │
                    │   │Handler1││Handler2││Handler3│   │
                    │   │(读处理)││(写处理)││(定时器)│   │
                    │   └────────┘└────────┘└────────┘   │
                    └─────────────────────────────────────┘
```

**Reactor 模式变体**：

```
1. 单 Reactor 单线程：
   Reactor ──► Handler（串行处理）
   适用：业务处理快

2. 单 Reactor 多线程：
   Reactor ──► 线程池 ──► Handler
   适用：业务处理慢

3. 主从 Reactor 多线程：
   MainReactor（接受连接）──► SubReactor（处理 I/O）──► 线程池
   适用：高并发
```

---

### 4.2 Proactor 模式

**面试问题**：Proactor 和 Reactor 有什么区别？

**答案**：

**Proactor（前摄器）模式**：基于异步 I/O，I/O 操作由操作系统完成，完成后通知应用程序。

```
                    ┌─────────────────────────────────────┐
                    │           Proactor                  │
                    │                                     │
   ┌────────────┐   │   ┌─────────────────────────────┐  │
   │  Client 1  │◄──┼───│    Async Operation          │  │
   └────────────┘   │   │    Processor                │  │
                    │   └──────────────┬──────────────┘  │
   ┌────────────┐   │                  │                 │
   │  Client 2  │◄──┤          异步读写请求             │
   └────────────┘   │                  ▼                 │
                    │   ┌─────────────────────────────┐  │
   ┌────────────┐   │   │        操作系统内核          │  │
   │  Client 3  │◄──┤   │        执行 I/O 操作        │  │
   └────────────┘   │   └──────────────┬──────────────┘  │
                    │                  │                 │
                    │            完成通知               │
                    │                  ▼                 │
                    │   ┌─────────────────────────────┐  │
                    │   │    Completion Handler       │  │
                    │   │       完成处理器            │  │
                    │   └─────────────────────────────┘  │
                    └─────────────────────────────────────┘
```

| 特性 | Reactor | Proactor |
|------|---------|----------|
| **I/O 操作** | 应用程序执行 | 操作系统执行 |
| **事件通知** | I/O 就绪时通知 | I/O 完成时通知 |
| **复杂度** | 较低 | 较高 |
| **平台** | 跨平台 | Windows IOCP、Linux io_uring |
| **代表** | libevent、libuv | Windows IOCP |

## 5. 高性能 I/O 技术

### 5.1 零拷贝 (Zero-Copy)

**面试问题**：什么是零拷贝？有哪些实现方式？

**答案**：

**传统数据传输（4 次拷贝）**：

```
发送文件到网络：

  应用程序                     内核

    read()    ◄─────────── 磁盘 → 内核缓冲区
        │                       ↓
        │                  拷贝到用户缓冲区
        ▼
    write()   ──────────► 拷贝到 socket 缓冲区
                               ↓
                          拷贝到网卡缓冲区
                               ↓
                              网络

拷贝次数：4（磁盘→内核、内核→用户、用户→socket、socket→网卡）
上下文切换：4 次
```

**mmap + write（3 次拷贝）**：

```c
void *addr = mmap(NULL, size, PROT_READ, MAP_PRIVATE, fd, 0);
write(sockfd, addr, size);
munmap(addr, size);
```

```
  应用程序                     内核

    mmap()    ◄─────────── 磁盘 → 内核缓冲区
        │                  (映射到用户空间，不拷贝)
        ▼
    write()   ──────────► 拷贝到 socket 缓冲区
                               ↓
                          拷贝到网卡缓冲区

拷贝次数：3
```

**sendfile（2 次拷贝）**：

```c
#include <sys/sendfile.h>
sendfile(sockfd, filefd, NULL, size);
```

```
  应用程序                     内核

  sendfile()  ──────────► 磁盘 → 内核缓冲区
                               ↓
                          拷贝到 socket 缓冲区
                               ↓
                          (DMA) 网卡

拷贝次数：2（磁盘→内核，内核→网卡）
全程在内核态，无用户态拷贝
```

**splice（0 次 CPU 拷贝）**：

```c
#include <fcntl.h>

int pipefd[2];
pipe(pipefd);

// 从文件读到管道
splice(filefd, NULL, pipefd[1], NULL, size, SPLICE_F_MOVE);
// 从管道写到 socket
splice(pipefd[0], NULL, sockfd, NULL, size, SPLICE_F_MOVE);
```

```
  应用程序                     内核

  splice()    ──────────► 磁盘 → (DMA) → 内核缓冲区
                               ↓
                          管道（仅传递引用）
                               ↓
                          socket → (DMA) → 网卡

CPU 拷贝次数：0（全部由 DMA 完成）
```

### 5.2 io_uring

**面试问题**：什么是 io_uring？

**答案**：

**io_uring**（Linux 5.1+）：Linux 最新的异步 I/O 接口，提供真正的异步 I/O 能力。

```
传统 I/O：每次操作都需要系统调用

io_uring：共享环形缓冲区，减少系统调用

┌─────────────────────────────────────────────────────────┐
│                     用户空间                            │
│                                                         │
│   ┌─────────────────────────────────────────────────┐  │
│   │              提交队列 (SQ)                      │  │
│   │         ┌───┬───┬───┬───┬───┐                   │  │
│   │         │ 1 │ 2 │ 3 │   │   │ ← 提交请求       │  │
│   │         └───┴───┴───┴───┴───┘                   │  │
│   └─────────────────────────────────────────────────┘  │
│                         │                               │
├─────────────────────────┼───────────────────────────────┤
│                         │                               │
│                     内核空间                            │
│                         ▼                               │
│   ┌─────────────────────────────────────────────────┐  │
│   │              完成队列 (CQ)                      │  │
│   │         ┌───┬───┬───┬───┬───┐                   │  │
│   │         │ A │ B │   │   │   │ → 获取结果       │  │
│   │         └───┴───┴───┴───┴───┘                   │  │
│   └─────────────────────────────────────────────────┘  │
│                                                         │
└─────────────────────────────────────────────────────────┘

优势：
1. 共享内存，减少拷贝
2. 批量提交，减少系统调用
3. 真正的异步 I/O
4. 支持文件和网络 I/O
```

## 6. 面试常见问题

### 6.1 高频问题汇总

**Q1：同步/异步和阻塞/非阻塞的区别？**
- 同步/异步：关注数据拷贝由谁完成（调用方/内核）
- 阻塞/非阻塞：关注等待数据时进程状态（挂起/立即返回）

**Q2：select、poll、epoll 的区别？**
- select：fd 限制 1024，每次拷贝全量，O(n)
- poll：无 fd 限制，每次拷贝全量，O(n)
- epoll：无 fd 限制，增量注册，O(1)

**Q3：epoll 为什么高效？**
- 红黑树存储 fd，增删 O(log n)
- 就绪链表存储就绪事件
- 事件驱动（回调），无需遍历
- 内存映射减少拷贝

**Q4：水平触发和边缘触发的区别？**
- 水平触发：有数据就一直通知
- 边缘触发：只在状态变化时通知一次
- 边缘触发需要非阻塞 + 循环读取

**Q5：什么是零拷贝？**
- 减少 CPU 参与的数据拷贝
- 技术：mmap、sendfile、splice
- 优势：减少 CPU 开销，提高吞吐量

**Q6：Reactor 和 Proactor 的区别？**
- Reactor：I/O 就绪通知，应用程序执行 I/O
- Proactor：I/O 完成通知，操作系统执行 I/O

## 7. 代码示例

### 7.1 epoll 服务器示例

```c
#include <sys/epoll.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

#define MAX_EVENTS 1024
#define PORT 8080

// 设置非阻塞
int set_nonblocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
}

int main() {
    // 创建监听 socket
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    set_nonblocking(listenfd);

    int opt = 1;
    setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in addr;
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = INADDR_ANY;
    addr.sin_port = htons(PORT);
    bind(listenfd, (struct sockaddr*)&addr, sizeof(addr));
    listen(listenfd, SOMAXCONN);

    // 创建 epoll
    int epfd = epoll_create1(0);

    struct epoll_event ev, events[MAX_EVENTS];
    ev.events = EPOLLIN;
    ev.data.fd = listenfd;
    epoll_ctl(epfd, EPOLL_CTL_ADD, listenfd, &ev);

    printf("Server listening on port %d\n", PORT);

    while (1) {
        int nfds = epoll_wait(epfd, events, MAX_EVENTS, -1);

        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == listenfd) {
                // 新连接
                struct sockaddr_in client_addr;
                socklen_t len = sizeof(client_addr);
                int clientfd = accept(listenfd,
                                      (struct sockaddr*)&client_addr, &len);

                if (clientfd < 0) continue;

                set_nonblocking(clientfd);
                ev.events = EPOLLIN | EPOLLET;  // 边缘触发
                ev.data.fd = clientfd;
                epoll_ctl(epfd, EPOLL_CTL_ADD, clientfd, &ev);

                printf("New connection: fd=%d\n", clientfd);
            } else if (events[i].events & EPOLLIN) {
                // 可读事件
                int fd = events[i].data.fd;
                char buf[1024];

                while (1) {
                    ssize_t n = read(fd, buf, sizeof(buf) - 1);

                    if (n > 0) {
                        buf[n] = '\0';
                        printf("Received from fd=%d: %s", fd, buf);

                        // 回显
                        write(fd, buf, n);
                    } else if (n == 0) {
                        // 连接关闭
                        printf("Connection closed: fd=%d\n", fd);
                        epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
                        close(fd);
                        break;
                    } else {
                        if (errno == EAGAIN) {
                            // 数据读完
                            break;
                        }
                        perror("read");
                        close(fd);
                        break;
                    }
                }
            }
        }
    }

    close(listenfd);
    close(epfd);
    return 0;
}
```
