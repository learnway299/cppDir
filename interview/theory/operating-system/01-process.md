# 01 - 进程管理 (Process Management)

## 简介

进程是操作系统进行资源分配和调度的基本单位。理解进程管理对于系统编程、性能优化和面试都至关重要。

**核心概念**：
- **进程**：程序的执行实例，拥有独立的地址空间
- **线程**：进程内的执行单元，共享进程资源
- **协程**：用户态的轻量级线程，由程序控制调度

---

## 1. 进程基础

### 1.1 什么是进程？进程与程序的区别？

**面试问题**：解释进程的概念，以及进程与程序的区别。

**答案**：

| 特性 | 程序 (Program) | 进程 (Process) |
|------|---------------|----------------|
| **本质** | 静态的可执行文件 | 动态的执行实例 |
| **存在形式** | 磁盘上的文件 | 内存中的运行体 |
| **生命周期** | 永久存在 | 有创建和终止 |
| **资源** | 无 | 拥有 CPU、内存、文件等 |
| **数量关系** | 一个程序 | 可产生多个进程 |

**类比**：程序是菜谱（静态指令），进程是按菜谱做菜的过程（动态执行）。

### 1.2 进程的组成结构

**面试问题**：进程由哪些部分组成？

**答案**：

```
┌─────────────────────────────────────────────┐
│                进程空间                       │
├─────────────────────────────────────────────┤
│  代码段 (Text)     │ 可执行指令（只读）        │
├─────────────────────────────────────────────┤
│  数据段 (Data)     │ 已初始化的全局/静态变量    │
├─────────────────────────────────────────────┤
│  BSS 段            │ 未初始化的全局/静态变量    │
├─────────────────────────────────────────────┤
│  堆 (Heap)         │ 动态分配内存（向上增长）    │
├─────────────────────────────────────────────┤
│  共享库映射区       │ 动态链接库                │
├─────────────────────────────────────────────┤
│  栈 (Stack)        │ 函数调用、局部变量（向下增长）│
├─────────────────────────────────────────────┤
│  内核空间          │ 内核代码和数据（用户不可访问）│
└─────────────────────────────────────────────┘
```

**进程控制块 (PCB)**：

```c
// Linux 内核中的 task_struct（简化版）
struct task_struct {
    // 进程标识
    pid_t pid;                    // 进程 ID
    pid_t tgid;                   // 线程组 ID

    // 进程状态
    volatile long state;          // 运行状态

    // 调度信息
    int prio;                     // 优先级
    struct sched_entity se;       // 调度实体

    // 内存管理
    struct mm_struct *mm;         // 内存描述符

    // 文件系统
    struct files_struct *files;   // 打开的文件
    struct fs_struct *fs;         // 文件系统信息

    // 信号处理
    struct signal_struct *signal;

    // 父子关系
    struct task_struct *parent;   // 父进程
    struct list_head children;    // 子进程链表
};
```

### 1.3 进程的状态与转换

**面试问题**：进程有哪些状态？如何转换？

**答案**：

**五状态模型**：

```
                    ┌──────────────┐
                    │    新建      │
                    │   (New)      │
                    └──────┬───────┘
                           │ 创建完成
                           ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│    阻塞      │◄───│    就绪      │◄───│    运行      │
│  (Blocked)   │    │   (Ready)    │    │  (Running)   │
└──────────────┘    └──────────────┘    └──────────────┘
       │                   ▲                   │
       │                   │                   │
       │    I/O 完成       │     时间片用完     │
       └───────────────────┘                   │
                                               ▼
                                        ┌──────────────┐
                                        │    终止      │
                                        │ (Terminated) │
                                        └──────────────┘
```

**状态说明**：

| 状态 | 英文 | 描述 |
|------|------|------|
| 新建 | New | 进程正在被创建 |
| 就绪 | Ready | 等待被调度到 CPU |
| 运行 | Running | 正在 CPU 上执行 |
| 阻塞 | Blocked/Waiting | 等待 I/O 或事件 |
| 终止 | Terminated | 执行完毕或被终止 |

**Linux 实际状态**：

```c

#define TASK_INTERRUPTIBLE     0x0001  // 可中断睡眠
#define TASK_UNINTERRUPTIBLE   0x0002  // 不可中断睡眠
#define __TASK_STOPPED         0x0004  // 停止（被信号）
#define __TASK_TRACED          0x0008  // 被调试跟踪
#define EXIT_DEAD              0x0010  // 最终死亡状态
#define EXIT_ZOMBIE            0x0020  // 僵尸状态
```

## 2. 进程、线程、协程

### 2.1 进程与线程的区别

**面试问题**：进程和线程有什么区别？

**答案**：

| 特性 | 进程 | 线程 |
|------|------|------|
| **定义** | 资源分配单位 | CPU 调度单位 |
| **地址空间** | 独立 | 共享进程地址空间 |
| **资源开销** | 大（需要独立资源） | 小（共享进程资源） |
| **创建/销毁** | 慢（毫秒级） | 快（微秒级） |
| **切换开销** | 大（需切换页表） | 小（仅切换寄存器） |
| **通信方式** | IPC（管道、共享内存等） | 直接读写共享内存 |
| **稳定性** | 一个崩溃不影响其他 | 一个崩溃可能导致整个进程崩溃 |
| **同步** | 复杂（需要 IPC） | 简单（但需要锁） |

**资源对比**：

```
进程独享：                          线程独享：
├── 地址空间                        ├── 栈
├── 全局变量                        ├── 寄存器
├── 堆                              ├── 线程 ID
├── 打开的文件                      ├── 错误号 (errno)
├── 信号处理器                      └── 线程私有数据 (TLS)
└── 子进程

线程共享（来自进程）：
├── 代码段
├── 数据段（全局变量）
├── 堆
├── 打开的文件描述符
├── 信号处理器
└── 当前工作目录
```

---

### 2.2 为什么要有线程？

**面试问题**：既然有了进程，为什么还需要线程？

**答案**：

```
1. 资源开销
   进程创建: fork() → 复制页表、文件描述符等 → 毫秒级
   线程创建: pthread_create() → 仅分配栈和 TCB → 微秒级

2. 通信效率
   进程间: 需要 IPC → 涉及内核 → 开销大
   线程间: 直接访问共享内存 → 无需内核 → 开销小

3. 上下文切换
   进程切换: 切换页表、刷新 TLB → 开销大
   线程切换: 仅切换寄存器和栈 → 开销小

4. 并发模型
   多进程: 适合 CPU 密集型、需要隔离
   多线程: 适合 I/O 密集型、需要共享数据
```

**实际应用场景**：

| 场景 | 选择 | 原因 |
|------|------|------|
| Web 服务器 | 多线程/多进程 | 需要同时处理多个请求 |
| 数据库服务 | 多线程 | 共享缓存和连接池 |
| 浏览器 | 多进程（标签页） | 隔离防止崩溃蔓延 |
| GUI 应用 | 多线程 | UI 线程 + 工作线程 |

### 2.3 协程 (Coroutine)

**面试问题**：什么是协程？与线程有什么区别？

**答案**：

协程是一种**用户态的轻量级线程**，由程序（而非操作系统）控制调度。

| 特性 | 线程 | 协程 |
|------|------|------|
| **调度者** | 操作系统内核 | 用户程序 |
| **切换方式** | 抢占式 | 协作式 |
| **切换开销** | 微秒级（需进入内核） | 纳秒级（用户态切换） |
| **栈大小** | MB 级（Linux 8MB） | KB 级（可按需增长） |
| **并发数** | 千级 | 百万级 |
| **阻塞影响** | 仅阻塞当前线程 | 可能阻塞整个线程 |

**协程实现原理**：

```cpp
// C++20 协程示例
#include <coroutine>
#include <iostream>

struct Generator {
    struct promise_type {
        int current_value;

        Generator get_return_object() {
            return Generator{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        std::suspend_always yield_value(int value) {
            current_value = value;
            return {};
        }
        void return_void() {}
        void unhandled_exception() {}
    };

    std::coroutine_handle<promise_type> handle;

    bool move_next() {
        handle.resume();
        return !handle.done();
    }

    int current_value() {
        return handle.promise().current_value;
    }
};

Generator range(int start, int end) {
    for (int i = start; i < end; ++i) {
        co_yield i;  // 挂起点，返回值
    }
}

void coroutine_example() {
    auto gen = range(0, 5);
    while (gen.move_next()) {
        std::cout << gen.current_value() << " ";  // 0 1 2 3 4
    }
}
```

**三者对比**：

```
            ┌─────────────────────────────────────────────────────┐
            │                    操作系统                          │
            │  ┌──────────────────────────────────────────────┐   │
            │  │              进程调度器                       │   │
            │  └──────────────────────────────────────────────┘   │
            │         │              │              │              │
            │    ┌────▼────┐   ┌────▼────┐   ┌────▼────┐         │
            │    │ 进程 A  │   │ 进程 B  │   │ 进程 C  │         │
            │    └────┬────┘   └────┬────┘   └─────────┘         │
            │         │              │                            │
            │    ┌────▼────┐   ┌────▼────┐                       │
            │    │ 线程调度 │   │ 线程调度 │                       │
            │    └────┬────┘   └────┬────┘                       │
            │    ┌────┴────┐   ┌────┴────┐                       │
            │    │T1 T2 T3 │   │T1 T2    │    ← 内核态调度       │
            └────┴─────────┴───┴─────────┴───────────────────────┘
                      │              │
                 ┌────▼────┐   ┌────▼────┐
                 │协程调度器│   │协程调度器│    ← 用户态调度
                 └────┬────┘   └────┬────┘
                 ┌────┴────┐   ┌────┴────┐
                 │C1 C2 C3 │   │C1 C2    │    ← 协程（用户态）
                 └─────────┘   └─────────┘
```

## 3. 进程控制

### 3.1 进程创建

**面试问题**：Linux 中如何创建进程？fork() 的原理是什么？

**答案**：

**fork() 系统调用**：

```c
#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>

int main() {
    printf("父进程 PID: %d\n", getpid());

    pid_t pid = fork();  // 创建子进程

    if (pid < 0) {
        // fork 失败
        perror("fork failed");
        return 1;
    } else if (pid == 0) {
        // 子进程
        printf("子进程 PID: %d, 父进程 PID: %d\n", getpid(), getppid());
    } else {
        // 父进程
        printf("父进程创建了子进程 PID: %d\n", pid);
        wait(NULL);  // 等待子进程结束
    }

    return 0;
}
```

**fork() 的工作原理**：

```
fork() 前：
┌─────────────────────────────────────┐
│            父进程                    │
│  ┌─────────┬─────────┬───────────┐  │
│  │  代码段  │  数据段  │    堆     │  │
│  └─────────┴─────────┴───────────┘  │
│  ┌─────────────────────────────────┐  │
│  │           页表                   │  │
│  └─────────────────────────────────┘  │
└─────────────────────────────────────┘

fork() 后（写时复制 Copy-on-Write）：
┌─────────────────┐    ┌─────────────────┐
│    父进程        │    │    子进程        │
│  ┌───────────┐  │    │  ┌───────────┐  │
│  │   页表    │  │    │  │   页表    │  │
│  └─────┬─────┘  │    │  └─────┬─────┘  │
└────────┼────────┘    └────────┼────────┘
         │                      │
         └────────┬─────────────┘
                  ▼
         ┌─────────────────┐
         │   物理内存页     │  ← 共享，标记为只读
         │  （写时复制）    │
         └─────────────────┘

当任一进程写入时：
┌─────────────────┐    ┌─────────────────┐
│    父进程        │    │    子进程        │
│  ┌───────────┐  │    │  ┌───────────┐  │
│  │   页表    │  │    │  │   页表    │  │
│  └─────┬─────┘  │    │  └─────┬─────┘  │
└────────┼────────┘    └────────┼────────┘
         │                      │
         ▼                      ▼
┌─────────────┐        ┌─────────────┐
│  物理页(原)  │        │  物理页(副本)│
└─────────────┘        └─────────────┘
```

**写时复制 (Copy-on-Write, COW) 优点**：
- 延迟复制：只有实际写入时才复制
- 减少内存开销：读取时共享
- 加速 fork()：无需立即复制所有页

### 3.2 进程的创建方式对比

**面试问题**：fork()、vfork()、clone() 有什么区别？

**答案**：

| 系统调用 | 地址空间 | 使用场景 |
|----------|----------|----------|
| `fork()` | 复制（COW） | 通用进程创建 |
| `vfork()` | 共享 | 立即 exec() 的场景 |
| `clone()` | 可选共享 | 创建线程或自定义共享 |

```c
// clone() 创建线程示例
#define _GNU_SOURCE
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>

#define STACK_SIZE (1024 * 1024)

int thread_func(void* arg) {
    printf("子线程运行中，参数: %d\n", *(int*)arg);
    return 0;
}

int main() {
    char* stack = malloc(STACK_SIZE);
    int arg = 42;

    // clone 标志：共享内存、文件、信号处理等
    int flags = CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND;

    pid_t pid = clone(thread_func, stack + STACK_SIZE, flags, &arg);

    waitpid(pid, NULL, 0);
    free(stack);
    return 0;
}
```

### 3.3 exec 系列函数

**面试问题**：exec() 系列函数的作用是什么？

**答案**：

`exec` 用于在当前进程中执行新程序，替换当前进程的代码段、数据段等。

```c
#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        // 子进程执行 ls 命令
        // execl: 参数列表形式
        execl("/bin/ls", "ls", "-la", NULL);

        // 如果 exec 成功，下面的代码不会执行
        perror("exec failed");
        _exit(1);
    } else {
        wait(NULL);
    }

    return 0;
}
```

**exec 家族**：

| 函数 | 参数形式 | 路径查找 | 环境变量 |
|------|----------|----------|----------|
| `execl` | 列表 | 完整路径 | 继承 |
| `execv` | 数组 | 完整路径 | 继承 |
| `execlp` | 列表 | PATH 搜索 | 继承 |
| `execvp` | 数组 | PATH 搜索 | 继承 |
| `execle` | 列表 | 完整路径 | 自定义 |
| `execve` | 数组 | 完整路径 | 自定义 |

### 3.4 孤儿进程与僵尸进程

**面试问题**：什么是孤儿进程和僵尸进程？如何处理？

**答案**：

**孤儿进程 (Orphan Process)**：
- 父进程先于子进程结束
- 子进程被 init 进程（PID=1）收养
- **无害**：init 会正确清理

```c
// 孤儿进程示例
int main() {
    pid_t pid = fork();

    if (pid > 0) {
        printf("父进程退出\n");
        exit(0);  // 父进程立即退出
    } else if (pid == 0) {
        sleep(5);  // 子进程继续运行
        printf("子进程的新父进程: %d\n", getppid());  // 将是 1 (init)
    }

    return 0;
}
```

**僵尸进程 (Zombie Process)**：
- 子进程结束，但父进程未调用 `wait()` 回收
- 子进程的 PCB 仍占用内核资源
- **有害**：大量僵尸会耗尽进程表

```c
// 僵尸进程示例
int main() {
    pid_t pid = fork();

    if (pid > 0) {
        sleep(60);  // 父进程不调用 wait()
    } else if (pid == 0) {
        printf("子进程退出，变成僵尸\n");
        exit(0);  // 子进程退出，但不会被回收
    }

    return 0;
}

// 查看僵尸进程：ps aux | grep Z
```

**解决僵尸进程的方法**：

```c
// 方法 1：父进程调用 wait()
pid_t pid = fork();
if (pid > 0) {
    wait(NULL);  // 等待子进程结束
}

// 方法 2：信号处理 SIGCHLD
#include <signal.h>

void sigchld_handler(int sig) {
    while (waitpid(-1, NULL, WNOHANG) > 0);
}

int main() {
    signal(SIGCHLD, sigchld_handler);
    // ... fork 子进程
}

// 方法 3：两次 fork（祖孙进程）
pid_t pid = fork();
if (pid == 0) {
    pid_t grandchild = fork();
    if (grandchild > 0) {
        exit(0);  // 子进程退出，孙进程被 init 收养
    }
    // 孙进程执行实际工作
} else {
    wait(NULL);  // 等待子进程
}
```

## 4. 进程调度

### 4.1 调度的基本概念

**面试问题**：什么是进程调度？有哪些调度时机？

**答案**：

**调度时机**：
1. 进程创建或终止
2. 进程从运行态进入阻塞态（I/O 等待）
3. 进程从阻塞态进入就绪态（I/O 完成）
4. 时间片用完
5. 更高优先级进程就绪（抢占式调度）

**调度类型**：

| 类型 | 描述 | 特点 |
|------|------|------|
| 非抢占式 | 进程主动放弃 CPU | 简单，但响应慢 |
| 抢占式 | 可被高优先级进程抢占 | 响应快，实现复杂 |

---

### 4.2 常见调度算法

**面试问题**：介绍常见的进程调度算法。

**答案**：

#### 1. 先来先服务 (FCFS, First-Come First-Served)

```
进程    到达时间    执行时间
P1      0           24
P2      1           3
P3      2           3

执行顺序：P1 → P2 → P3
平均等待时间：(0 + 23 + 25) / 3 = 16

问题：护航效应（长进程导致短进程等待太久）
```

#### 2. 短作业优先 (SJF, Shortest Job First)

```
进程    到达时间    执行时间
P1      0           7
P2      2           4
P3      4           1
P4      5           4

非抢占式 SJF 执行顺序：P1 → P3 → P2 → P4
平均等待时间：(0 + 6 + 3 + 7) / 4 = 4

优点：平均等待时间最短
缺点：可能饥饿，需要预知执行时间
```

#### 3. 最短剩余时间优先 (SRTF, Shortest Remaining Time First)

```
抢占式 SJF：当新进程到达时，比较剩余时间

时间    运行进程    就绪队列
0       P1(7)       -
2       P2(4)       P1(5)      // P2 更短，抢占
4       P3(1)       P1(5),P2(2) // P3 更短，抢占
5       P2(2)       P1(5),P4(4) // P3 完成
7       P4(4)       P1(5)       // P2 完成
11      P1(5)       -           // P4 完成
```

#### 4. 优先级调度 (Priority Scheduling)

```c
// 优先级数值越小，优先级越高
进程    优先级    执行时间
P1      3         10
P2      1         1
P3      4         2
P4      2         5

执行顺序：P2(1) → P4(5) → P1(10) → P3(2)

问题：低优先级进程可能饥饿
解决：老化（随时间提高等待进程的优先级）
```

#### 5. 时间片轮转 (Round Robin, RR)

```
时间片 = 4

进程    执行时间
P1      24
P2      3
P3      3

时间    运行    就绪队列
0-4     P1      P2, P3
4-7     P2      P3, P1(20)     // P2 完成
7-10    P3      P1(20)         // P3 完成
10-14   P1
14-18   P1
...
30      P1 完成

特点：公平，响应时间好
问题：时间片过大退化为 FCFS，过小切换开销大
```

#### 6. 多级反馈队列 (Multilevel Feedback Queue)

```
┌─────────────────────────────────────────┐
│  队列 0（最高优先级）：时间片 = 8ms      │
│  [P1] [P4]                               │
├─────────────────────────────────────────┤
│  队列 1：时间片 = 16ms                   │
│  [P2] [P5]                               │
├─────────────────────────────────────────┤
│  队列 2：时间片 = 32ms                   │
│  [P3]                                    │
├─────────────────────────────────────────┤
│  队列 3（最低优先级）：FCFS               │
│  [P6] [P7]                               │
└─────────────────────────────────────────┘

规则：
1. 新进程进入最高优先级队列
2. 时间片内未完成则降级
3. 高优先级队列为空时才调度低优先级
4. 可设置老化机制防止饥饿
```

### 4.3 Linux 调度器

**面试问题**：Linux 内核使用什么调度算法？

**答案**：

**完全公平调度器 (CFS, Completely Fair Scheduler)**：

```
核心思想：维护每个进程的虚拟运行时间 (vruntime)
         优先调度 vruntime 最小的进程

vruntime = 实际运行时间 × (NICE_0_LOAD / 进程权重)

权重与 nice 值的关系：
nice = 0  → 权重 = 1024
nice = -20 → 权重 = 88761（优先级最高）
nice = 19  → 权重 = 15（优先级最低）
```

**CFS 使用红黑树**：

```
                    ┌─────┐
                    │  20 │  ← vruntime = 20
                    └──┬──┘
              ┌────────┴────────┐
           ┌──┴──┐           ┌──┴──┐
           │ 15  │           │ 30  │
           └──┬──┘           └──┬──┘
        ┌────┴────┐       ┌────┴────┐
     ┌──┴──┐   ┌──┴──┐ ┌──┴──┐   ┌──┴──┐
     │ 10  │   │ 18  │ │ 25  │   │ 35  │
     └─────┘   └─────┘ └─────┘   └─────┘
        ↑
     下一个被调度的进程（最左节点，vruntime 最小）
```

## 5. 进程间通信 (IPC)

### 5.1 IPC 方式概述

**面试问题**：进程间通信有哪些方式？

**答案**：

| 方式 | 特点 | 适用场景 |
|------|------|----------|
| 管道 | 半双工，父子进程 | 简单数据传递 |
| 命名管道 | 半双工，无关进程 | 简单 IPC |
| 消息队列 | 消息格式，异步 | 结构化数据 |
| 共享内存 | 最快，需同步 | 大量数据共享 |
| 信号量 | 同步原语 | 进程同步 |
| 信号 | 异步通知 | 事件通知 |
| Socket | 跨网络 | 网络通信 |

### 5.2 管道 (Pipe)

```c
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main() {
    int pipefd[2];  // pipefd[0]: 读端, pipefd[1]: 写端

    if (pipe(pipefd) == -1) {
        perror("pipe");
        return 1;
    }

    pid_t pid = fork();

    if (pid == 0) {
        // 子进程读取
        close(pipefd[1]);  // 关闭写端

        char buf[100];
        read(pipefd[0], buf, sizeof(buf));
        printf("子进程收到: %s\n", buf);

        close(pipefd[0]);
    } else {
        // 父进程写入
        close(pipefd[0]);  // 关闭读端

        const char* msg = "Hello from parent!";
        write(pipefd[1], msg, strlen(msg) + 1);

        close(pipefd[1]);
        wait(NULL);
    }

    return 0;
}
```

### 5.3 共享内存 (Shared Memory)

```c
#include <sys/shm.h>
#include <stdio.h>
#include <string.h>

#define SHM_SIZE 1024

int main() {
    // 创建共享内存
    int shmid = shmget(IPC_PRIVATE, SHM_SIZE, IPC_CREAT | 0666);

    pid_t pid = fork();

    if (pid == 0) {
        // 子进程
        char* shm = shmat(shmid, NULL, 0);
        printf("子进程读取: %s\n", shm);
        shmdt(shm);
    } else {
        // 父进程
        char* shm = shmat(shmid, NULL, 0);
        strcpy(shm, "Hello Shared Memory!");
        shmdt(shm);

        wait(NULL);
        shmctl(shmid, IPC_RMID, NULL);  // 删除共享内存
    }

    return 0;
}
```

### 5.4 消息队列 (Message Queue)

```c
#include <sys/msg.h>
#include <stdio.h>
#include <string.h>

struct message {
    long mtype;
    char mtext[100];
};

int main() {
    int msgid = msgget(IPC_PRIVATE, IPC_CREAT | 0666);

    pid_t pid = fork();

    if (pid == 0) {
        // 子进程接收
        struct message msg;
        msgrcv(msgid, &msg, sizeof(msg.mtext), 1, 0);
        printf("子进程收到: %s\n", msg.mtext);
    } else {
        // 父进程发送
        struct message msg;
        msg.mtype = 1;
        strcpy(msg.mtext, "Hello Message Queue!");
        msgsnd(msgid, &msg, strlen(msg.mtext) + 1, 0);

        wait(NULL);
        msgctl(msgid, IPC_RMID, NULL);
    }

    return 0;
}
```

## 6. 面试常见问题

### 6.1 高频问题汇总

**Q1：进程和线程的区别？**
- 进程是资源分配单位，线程是 CPU 调度单位
- 进程有独立地址空间，线程共享进程地址空间
- 进程切换开销大，线程切换开销小
- 进程通信需要 IPC，线程可直接读写共享内存

**Q2：fork() 返回值的含义？**
- `<0`：创建失败
- `=0`：在子进程中
- `>0`：在父进程中，值为子进程 PID

**Q3：写时复制 (COW) 是什么？**
- fork() 后父子进程共享物理页
- 页表标记为只读
- 任一进程写入时触发缺页异常，复制该页
- 优点：减少不必要的复制，加速 fork()

**Q4：如何避免僵尸进程？**
1. 父进程调用 `wait()` 或 `waitpid()`
2. 信号处理 `SIGCHLD`
3. 两次 fork（让 init 收养孙进程）
4. 设置 `SIGCHLD` 为 `SIG_IGN`

**Q5：进程调度算法对比？**
- FCFS：简单但有护航效应
- SJF：平均等待最短但可能饥饿
- RR：公平但时间片选择困难
- 多级反馈队列：综合性能好

**Q6：Linux CFS 调度器原理？**
- 基于虚拟运行时间 (vruntime)
- 使用红黑树维护就绪队列
- O(log n) 时间复杂度选择下一个进程
- 通过权重实现优先级

### 7.2 上下文切换过程

```
                    上下文切换流程

进程 A 运行中 ─────────────────────────────────────→

1. 触发切换（时钟中断/系统调用/I/O 等待）
           │
           ▼
2. 保存 A 的上下文到 PCB
   ├── 通用寄存器
   ├── 程序计数器 (PC)
   ├── 栈指针 (SP)
   ├── 页表基址寄存器
   └── 浮点寄存器
           │
           ▼
3. 更新 A 的状态（运行→就绪/阻塞）
           │
           ▼
4. 调度器选择进程 B
           │
           ▼
5. 加载 B 的上下文
   ├── 恢复寄存器
   ├── 切换页表（刷新 TLB）
   └── 恢复 PC
           │
           ▼
6. 进程 B 开始运行 ───────────────────────────────→
```

**切换开销**：
- 直接开销：寄存器保存/恢复、页表切换
- 间接开销：TLB 失效、Cache 失效、流水线刷新
