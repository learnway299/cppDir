# 02 - 内存管理 (Memory Management)

## 简介

内存管理是操作系统的核心功能之一，负责高效、安全地分配和管理物理内存和虚拟内存。

**核心概念**：
- **虚拟 内存**：为每个进程提供独立的地址空间
- **分页/分段**：内存空间的划分方式
- **页面置换**：物理内存不足时的换页策略
- **TLB**：加速地址转换的硬件缓存

---

## 1. 内存基础

### 1.1 物理地址与虚拟地址

**面试问题**：什么是虚拟内存？为什么需要虚拟内存？

**答案**：

**虚拟内存 (Virtual Memory)**：
- 每个进程拥有独立的虚拟地址空间
- 虚拟地址通过 MMU 转换为物理地址
- 实现内存隔离和保护

```
┌─────────────────────────────────────────────────────────┐
│                    虚拟地址空间                          │
│                                                          │
│  进程 A              进程 B              进程 C          │
│ ┌────────┐         ┌────────┐         ┌────────┐        │
│ │0~4GB   │         │0~4GB   │         │0~4GB   │        │
│ │虚拟地址 │         │虚拟地址 │         │虚拟地址 │        │
│ └───┬────┘         └───┬────┘         └───┬────┘        │
│     │                  │                  │              │
│     ▼                  ▼                  ▼              │
│  ┌─────────────────────────────────────────────┐        │
│  │              MMU（内存管理单元）             │        │
│  │              + 页表                         │        │
│  └─────────────────────────────────────────────┘        │
│                        │                                 │
│                        ▼                                 │
│  ┌─────────────────────────────────────────────┐        │
│  │            物理内存 (RAM)                    │        │
│  │  ┌────┬────┬────┬────┬────┬────┬────┬────┐  │        │
│  │  │ 0  │ 1  │ 2  │ 3  │ 4  │ 5  │ 6  │ 7  │  │        │
│  │  └────┴────┴────┴────┴────┴────┴────┴────┘  │        │
│  └─────────────────────────────────────────────┘        │
└─────────────────────────────────────────────────────────┘
```

**虚拟内存的优点**：

| 优点 | 说明 |
|------|------|
| **隔离性** | 进程无法访问其他进程的内存 |
| **安全性** | 内核空间与用户空间分离 |
| **简化编程** | 每个进程有统一的地址空间布局 |
| **超额分配** | 可分配超过物理内存的虚拟内存 |
| **共享** | 多进程可共享同一物理页（如共享库） |
| **按需加载** | 只加载实际使用的页面 |

### 1.2 32 位 vs 64 位地址空间

**面试问题**：32 位和 64 位系统的地址空间有什么区别？

**答案**：

| 特性 | 32 位 | 64 位 |
|------|-------|-------|
| **地址空间** | 4GB (2^32) | 16EB (2^64 理论) |
| **用户空间** | 3GB | 128TB (Linux) |
| **内核空间** | 1GB | 128TB |
| **单进程限制** | 最大 4GB 内存 | 几乎无限制 |
| **指针大小** | 4 字节 | 8 字节 |

```
32 位 Linux 地址空间：

           │                 │

64 位 Linux 地址空间：

0xFFFFFFFFFFFFFFFF ┌─────────────────┐
                   │   内核空间      │ 128TB

                   │  非规范地址     │ (空洞)
0x00007FFFFFFFFFFF ├─────────────────┤
                   │                 │
                   │   用户空间      │ 128TB
                   │                 │
0x0000000000000000 └─────────────────┘
```

## 2. 分页与分段

### 2.1 分页机制 (Paging)

**面试问题**：什么是分页？页表是如何工作的？

**答案**：

**分页基本概念**：
- **页 (Page)**：虚拟内存的固定大小块（通常 4KB）
- **页框 (Frame)**：物理内存的固定大小块
- **页表 (Page Table)**：虚拟页到物理页框的映射

```
虚拟地址结构（32 位，4KB 页）：

┌──────────────────────┬──────────────────────┐
│    页号 (20 位)       │   页内偏移 (12 位)    │
└──────────────────────┴──────────────────────┘
        │                       │
        ▼                       │
   ┌────────────┐               │
   │   页表     │               │
   │ ┌────────┐ │               │
   │ │ PTE 0  │ │               │
   │ ├────────┤ │               │
   │ │ PTE 1  │ │               │
   │ ├────────┤ │               │
   │ │  ...   │ │               │
   │ ├────────┤ │               │
   │ │ PTE N  │─┼──→ 物理页框号 │
   │ └────────┘ │       │       │
   └────────────┘       │       │
                        ▼       ▼
                   ┌─────────────────┐
                   │   物理地址      │
                   └─────────────────┘
```

**页表项 (PTE) 结构**：

```c
// x86 页表项（简化）
struct page_table_entry {
    unsigned int present : 1;      // 是否在内存中
    unsigned int rw : 1;           // 读/写权限
    unsigned int user : 1;         // 用户/内核模式
    unsigned int pwt : 1;          // 页级写穿透
    unsigned int pcd : 1;          // 页级缓存禁用
    unsigned int accessed : 1;     // 访问位
    unsigned int dirty : 1;        // 脏页位
    unsigned int pat : 1;          // 页属性表
    unsigned int global : 1;       // 全局页
    unsigned int available : 3;    // 可用位
    unsigned int frame : 20;       // 物理页框号
};
```

### 2.2 多级页表

**面试问题**：为什么需要多级页表？

**答案**：

**问题**：单级页表太大
- 32 位系统：2^20 个页表项 × 4B = 4MB/进程
- 64 位系统：2^52 个页表项，根本不可行

**解决方案**：多级页表

```
     │          │              │
     ▼          │              │
┌─────────┐     │              │
│ 页目录   │     │              │
│ (1024项)│     │              │
├─────────┤     │              │
│   ...   │     │              │
│ ┌─────┐ │     │              │
│ │ PDE │─┼─────┘              │
│ └─────┘ │                    │
└─────────┘                    │
     │                         │
     ▼                         │
┌─────────┐                    │
│  页表   │                    │
│ (1024项)│                    │
├─────────┤                    │
│   ...   │                    │
│ ┌─────┐ │                    │
│ │ PTE │─┼──→ 物理页框 ───────┘
│ └─────┘ │         │
└─────────┘         ▼
              物理地址
```

**x86-64 四级页表**：

```
虚拟地址（48 位有效）：

┌───────┬───────┬───────┬───────┬──────────────┐
│ PML4  │  PDP  │  PD   │  PT   │   Offset     │

```

**多级页表优点**：
- 未使用的页表不需要分配
- 大大减少内存占用
- 支持稀疏地址空间

### 2.3 分段机制 (Segmentation)

**面试问题**：分段和分页有什么区别？

**答案**：

| 特性 | 分页 | 分段 |
|------|------|------|
| **大小** | 固定（如 4KB） | 可变 |
| **可见性** | 对程序透明 | 程序员可见 |
| **目的** | 实现虚拟内存 | 逻辑组织代码/数据 |
| **碎片** | 内碎片 | 外碎片 |
| **地址** | 单一线性 | 段号 + 段内偏移 |

```
分段地址转换：

逻辑地址：
┌───────────────┬────────────────┐
│   段号        │    段内偏移     │
└───────┬───────┴───────┬────────┘
        │               │
        ▼               │
   ┌─────────────┐      │
   │   段表      │      │
   ├─────────────┤      │
   │  段号 │ 基址│      │
   │   0  │ 1000│      │
   │   1  │ 5000│──────┤
   │   2  │ 8000│      │
   └─────────────┘      │
        │               │
        ▼               ▼
   基址 5000  +  偏移 200  = 物理地址 5200
```

**段页式（现代系统）**：
- 先分段，再在段内分页
- 结合两者优点
- x86 支持但 Linux 几乎不使用分段

## 3. TLB (Translation Lookaside Buffer)

### 3.1 TLB 原理

**面试问题**：什么是 TLB？为什么需要 TLB？

**答案**：

**问题**：多级页表需要多次内存访问
- 4 级页表 = 4 次内存访问 + 1 次数据访问 = 5 次

**解决方案**：TLB（快表）
- 缓存最近使用的页表项
- 查找时间：1 CPU 周期 vs 内存访问 100+ 周期

```
地址转换过程：

    虚拟地址
        │
        ▼
   ┌─────────┐
   │  TLB    │ ◄─── 快速查找
   │  查找   │
   └────┬────┘
        │
   ┌────┴────┐
   │命中？   │
   └────┬────┘
     ╱     ╲
   是       否
   │         │
   ▼         ▼
物理地址   ┌─────────┐
   │      │ 页表遍历 │ ◄─── 慢速（多次内存访问）
   ▼      └────┬────┘
  数据         │
              ▼
         更新 TLB
              │
              ▼
          物理地址
              │
              ▼
            数据
```

**TLB 结构**：

```
┌─────────────────────────────────────────────────┐
│                    TLB                          │
├─────────────────────────────────────────────────┤
│  虚拟页号  │  物理页框号  │  有效位  │  权限位  │
├───────────┼─────────────┼─────────┼──────────┤
│  0x12345  │   0x5678    │    1    │   RW     │
│  0x12346  │   0x9ABC    │    1    │   R      │
│  0xABCDE  │   0x1234    │    1    │   RWX    │
│    ...    │    ...      │   ...   │   ...    │
└─────────────────────────────────────────────────┘

TLB 命中：1 次访问
TLB 未命中：1 + 4（页表遍历）= 5 次访问
```

**TLB 性能影响**：

```c
// 示例：TLB 性能差异
// 假设 TLB 命中时间 = 1 周期，内存访问 = 100 周期

// TLB 命中率 95%：
// 平均访问时间 = 0.95 × 1 + 0.05 × 401 = 21 周期

// TLB 命中率 99%：
// 平均访问时间 = 0.99 × 1 + 0.01 × 401 = 5 周期
```

## 4. 页面置换算法

### 4.1 页面置换概述

**面试问题**：什么是页面置换？什么时候触发？

**答案**：

当物理内存不足时，需要选择一个页面换出到磁盘（swap），为新页面腾出空间。

**缺页异常处理流程**：

```
程序访问虚拟地址
        │
        ▼
   ┌─────────┐
   │ 页表查找 │
   └────┬────┘
        │
   ┌────┴────┐
   │ 页在内存？│
   └────┬────┘
     ╱     ╲
   是       否
   │         │
   ▼         ▼
正常访问   缺页异常 (Page Fault)
              │
              ▼
        ┌───────────┐
        │ 有空闲页框？│
        └─────┬─────┘
          ╱       ╲
        是         否
        │           │
        ▼           ▼
    分配页框    页面置换算法
        │           │
        ▼           ▼
    从磁盘读入   选择牺牲页
        │           │
        ▼           ▼
    更新页表    写回磁盘（如果脏页）
        │           │
        └─────┬─────┘
              ▼
        重新执行指令
```

### 4.2 常见页面置换算法

**面试问题**：介绍常见的页面置换算法。

#### 1. 最优算法 (OPT, Optimal)

```
原理：置换未来最长时间不会被访问的页面
问题：需要预知未来，实际无法实现
用途：作为算法性能的理论上界

示例（3 个页框）：
引用序列：7, 0, 1, 2, 0, 3, 0, 4, 2, 3

时间  访问  页框状态    缺页
1     7    [7, -, -]    是
2     0    [7, 0, -]    是
3     1    [7, 0, 1]    是
4     2    [2, 0, 1]    是 (置换 7，因为 7 未来不再访问)
5     0    [2, 0, 1]    否
6     3    [2, 0, 3]    是 (置换 1)
7     0    [2, 0, 3]    否
8     4    [2, 4, 3]    是 (置换 0)
9     2    [2, 4, 3]    否
10    3    [2, 4, 3]    否

缺页次数：6
```

#### 2. 先进先出 (FIFO, First-In First-Out)

```
原理：置换最早进入内存的页面
实现：队列

示例（3 个页框）：
引用序列：7, 0, 1, 2, 0, 3, 0, 4, 2, 3

时间  访问  页框状态    缺页
1     7    [7, -, -]    是
2     0    [7, 0, -]    是
3     1    [7, 0, 1]    是
4     2    [2, 0, 1]    是 (置换 7)
5     0    [2, 0, 1]    否
6     3    [2, 3, 1]    是 (置换 0)
7     0    [2, 3, 0]    是 (置换 1)
8     4    [4, 3, 0]    是 (置换 2)
9     2    [4, 2, 0]    是 (置换 3)
10    3    [4, 2, 3]    是 (置换 0)

缺页次数：9

问题：Belady 异常 - 增加页框数可能导致更多缺页
```

#### 3. 最近最少使用 (LRU, Least Recently Used)

```
原理：置换最近最长时间未被访问的页面
思想：过去的行为预测未来

示例（3 个页框）：
引用序列：7, 0, 1, 2, 0, 3, 0, 4, 2, 3

时间  访问  页框状态    LRU 顺序        缺页
1     7    [7, -, -]    7              是
2     0    [7, 0, -]    7, 0           是
3     1    [7, 0, 1]    7, 0, 1        是
4     2    [2, 0, 1]    0, 1, 2        是 (置换 7)
5     0    [2, 0, 1]    1, 2, 0        否
6     3    [2, 0, 3]    2, 0, 3        是 (置换 1)
7     0    [2, 0, 3]    2, 3, 0        否
8     4    [4, 0, 3]    3, 0, 4        是 (置换 2)
9     2    [4, 0, 2]    0, 4, 2        是 (置换 3)
10    3    [4, 3, 2]    4, 2, 3        是 (置换 0)

缺页次数：8
```

**LRU 实现方式**：

```cpp
// 方法 1：链表 + 哈希表（O(1) 操作）
class LRUCache {
    int capacity;
    list<pair<int, int>> cache;  // key-value 双向链表
    unordered_map<int, list<pair<int, int>>::iterator> map;  // key -> 链表迭代器

public:
    LRUCache(int cap) : capacity(cap) {}

    int get(int key) {
        if (map.find(key) == map.end()) return -1;
        // 移到链表头部
        auto it = map[key];
        cache.splice(cache.begin(), cache, it);
        return it->second;
    }

    void put(int key, int value) {
        if (map.find(key) != map.end()) {
            // 更新并移到头部
            auto it = map[key];
            it->second = value;
            cache.splice(cache.begin(), cache, it);
        } else {
            if (cache.size() == capacity) {
                // 删除尾部（最久未使用）
                map.erase(cache.back().first);
                cache.pop_back();
            }
            cache.push_front({key, value});
            map[key] = cache.begin();
        }
    }
};
```

#### 4. 时钟算法 (Clock / Second Chance)

```
原理：FIFO 的改进版，给每页第二次机会

实现：
- 环形链表 + 访问位
- 指针指向下一个候选页
- 访问位 = 1：清零，移动指针
- 访问位 = 0：置换该页

┌───┬───┬───┬───┬───┬───┬───┬───┐
│ A │ B │ C │ D │ E │ F │ G │ H │
│ 1 │ 0 │ 1 │ 1 │ 0 │ 1 │ 0 │ 1 │
└───┴───┴───┴───┴───┴───┴───┴───┘
      ↑
    指针

需要置换时：
1. 检查 B，访问位 = 0，置换 B
2. 如果 B 访问位 = 1，清零，移动到 C

优点：近似 LRU，实现简单高效
```

#### 5. 改进时钟算法（考虑脏页）

```
页面分类：
(0, 0) - 未访问，未修改 → 最佳选择
(0, 1) - 未访问，已修改 → 需要写回
(1, 0) - 已访问，未修改 → 可能再次使用
(1, 1) - 已访问，已修改 → 最不希望置换

扫描顺序：
1. 第一轮：找 (0, 0)
2. 第二轮：找 (0, 1)，同时清除访问位
3. 第三轮：找 (0, 0)
4. 第四轮：找 (0, 1)
```

### 4.3 算法对比

| 算法 | 时间复杂度 | 优点 | 缺点 |
|------|------------|------|------|
| OPT | N/A | 缺页率最低 | 无法实现 |
| FIFO | O(1) | 实现简单 | Belady 异常 |
| LRU | O(1)* | 性能接近 OPT | 硬件支持代价高 |
| Clock | O(1) | 近似 LRU，开销小 | 不如纯 LRU 精确 |

## 5. 内存分配

### 5.1 内核内存分配器

**面试问题**：Linux 内核使用什么内存分配算法？

**答案**：

#### Buddy System（伙伴系统）

```
原理：按 2^n 个页为单位分配

空闲链表：
Order 0 (1 页):   [块] [块] [块]
Order 1 (2 页):   [块] [块]
Order 2 (4 页):   [块]
Order 3 (8 页):   [块]
...
Order 10 (1024 页): [块]

分配 5 页：
1. 5 页需要 8 页块 (Order 3)
2. 没有 Order 3，分裂 Order 4（16 页）
3. 分裂：[16] → [8] + [8]
4. 分配一个 [8]，另一个加入 Order 3 链表

释放时：
- 检查伙伴块是否空闲
- 如果是，合并成更大的块
```

```
                    初始状态（16 页）
                    ┌─────────────────┐
                    │       16        │
                    └─────────────────┘

                    分配 3 页（需要 4 页块）
                    ┌───────┬───────┬───────┬───────┐
                    │   4   │   4   │       8       │
                    │(分配) │(空闲) │    (空闲)     │
                    └───────┴───────┴───────────────┘

                    释放 3 页
                    ┌───────────────┬───────────────┐
                    │       8       │       8       │
                    │    (合并)     │    (空闲)     │
                    └───────────────┴───────────────┘

                    继续合并
                    ┌─────────────────────────────────┐
                    │              16                 │
                    └─────────────────────────────────┘
```

**优点**：快速分配和释放，减少外碎片
**缺点**：内碎片（分配 5 页却占用 8 页）

#### Slab 分配器

```
原理：为特定大小的对象预分配缓存

┌─────────────────────────────────────────────────────┐
│                     Slab 缓存                       │
├─────────────────────────────────────────────────────┤
│  task_struct 缓存 │  inode 缓存  │  dentry 缓存    │
├───────────────────┼──────────────┼─────────────────┤
│  [obj][obj][obj]  │ [obj][obj]   │ [obj][obj][obj] │
│  [obj][obj][空]   │ [obj][空]    │ [obj][空][空]   │
└───────────────────┴──────────────┴─────────────────┘

三种 Slab 状态：
- Full：所有对象已分配
- Partial：部分对象已分配
- Empty：所有对象空闲
```

```c
// 内核使用示例
struct kmem_cache *task_cache;

// 创建缓存
task_cache = kmem_cache_create("task_struct",
                               sizeof(struct task_struct),
                               0,
                               SLAB_HWCACHE_ALIGN,
                               NULL);

// 分配对象
struct task_struct *task = kmem_cache_alloc(task_cache, GFP_KERNEL);

// 释放对象
kmem_cache_free(task_cache, task);

// 销毁缓存
kmem_cache_destroy(task_cache);
```

**优点**：
- 减少分配/释放开销（对象重用）
- 减少内碎片
- 提高 CPU 缓存命中率

**答案**：

```
malloc 分配策略：

                    ┌─────────────┐
                    │   malloc    │
                    └──────┬──────┘
                           │
```

```
Fast Bins（小于 64 字节）：

- 不合并，快速分配

- 刚释放的块暂存区
- 下次 malloc 时整理
```

## 6. 内存映射 (mmap)

### 6.1 mmap 原理

**面试问题**：mmap 是什么？有什么用途？

**答案**：

```c
#include <sys/mman.h>

// mmap 函数原型
void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);

// 参数说明：
// addr: 建议映射地址（通常为 NULL，由内核选择）
// length: 映射长度
// prot: 保护标志（PROT_READ, PROT_WRITE, PROT_EXEC）
// flags: 映射类型（MAP_SHARED, MAP_PRIVATE, MAP_ANONYMOUS）
// fd: 文件描述符（匿名映射为 -1）
// offset: 文件偏移
```

**mmap 类型**：

| 类型 | 说明 | 用途 |
|------|------|------|
| 文件映射 (共享) | 多进程共享，修改写回文件 | 共享内存、数据库 |
| 文件映射 (私有) | 写时复制 | 加载程序/库 |
| 匿名映射 (共享) | 多进程共享，无文件 | fork 后共享内存 |
| 匿名映射 (私有) | 私有内存 | malloc 大块分配 |

**文件映射示例**：

```c
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main() {
    int fd = open("data.txt", O_RDWR);
    size_t size = 4096;

    // 映射文件到内存
    char *map = mmap(NULL, size, PROT_READ | PROT_WRITE,
                     MAP_SHARED, fd, 0);

    if (map == MAP_FAILED) {
        perror("mmap");
        return 1;
    }

    // 直接读写内存，等同于读写文件
    printf("内容: %s\n", map);
    map[0] = 'X';  // 修改会写回文件

    // 解除映射
    munmap(map, size);
    close(fd);

    return 0;
}
```

**mmap vs read/write**：

| 特性 | mmap | read/write |
|------|------|------------|
| 数据拷贝 | 零拷贝（直接访问页缓存） | 内核缓冲区 → 用户缓冲区 |
| 随机访问 | 高效（指针操作） | 需要 lseek |
| 顺序读取大文件 | 可能触发大量缺页 | 预读优化好 |
| 小文件 | 开销较大 | 更合适 |

## 7. 面试常见问题

### 7.1 高频问题汇总

**Q1：什么是虚拟内存？优点是什么？**
- 每个进程有独立的虚拟地址空间
- 优点：隔离、安全、超额分配、共享、按需加载

**Q2：分页和分段的区别？**
- 分页：固定大小，对程序透明，内碎片
- 分段：可变大小，程序员可见，外碎片

**Q3：为什么需要多级页表？**
- 单级页表太大（4MB/进程）
- 多级页表只分配使用的部分
- 支持稀疏地址空间

**Q4：TLB 是什么？作用是什么？**
- 页表项的硬件缓存
- 加速地址转换（1 周期 vs 400+ 周期）
- TLB 命中率对性能影响巨大

**Q5：常见页面置换算法？**
- OPT：理论最优，无法实现
- FIFO：简单，有 Belady 异常
- LRU：近似最优，实现复杂
- Clock：近似 LRU，实现简单

**Q6：什么是内存碎片？如何解决？**
- 内碎片：分配的比需要的大（分页）
- 外碎片：空闲内存分散（分段）
- 解决：压缩、Buddy 系统、Slab 分配

**Q7：malloc 和 mmap 的区别？**
- malloc：小块用 brk（堆），大块用 mmap
- mmap：直接映射内存，可映射文件

**Q8：什么是写时复制 (COW)？**
- fork 后父子共享物理页
- 写入时才复制
- 节省内存，加速 fork

## 8. 深入原理

### 8.1 缺页异常类型

```
缺页异常分类：

1. Minor Page Fault（次要缺页）
   - 页在内存中，但页表未建立
   - 例：COW、匿名页首次访问
   - 处理：建立映射，无需磁盘 I/O

2. Major Page Fault（主要缺页）
   - 页不在内存，需要从磁盘加载
   - 例：换出的页、文件映射页
   - 处理：磁盘 I/O，代价高

3. Invalid Page Fault（无效缺页）
   - 访问非法地址
   - 例：空指针、越界访问
   - 处理：发送 SIGSEGV 信号
```
