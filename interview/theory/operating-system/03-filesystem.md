# 03 - 文件系统 (File System)

## 简介

文件系统是操作系统用于管理磁盘数据的核心组件，负责文件的组织、存储、检索和保护。

**核心概念**：
- **inode**：文件元数据存储结构
- **文件描述符**：进程访问文件的句柄
- **VFS**：虚拟文件系统抽象层
- **缓存机制**：提高文件访问性能

---

## 1. 文件系统基础

### 1.1 文件的概念

**面试问题**：什么是文件？文件系统的作用是什么？

**答案**：

**文件**：具有符号名的相关数据的集合，是逻辑存储单位。

**文件系统的作用**：
1. 管理磁盘空间（分配/释放）
2. 实现文件的按名存取
3. 提供文件共享与保护机制
4. 维护文件的目录结构

**文件类型**：

| 类型 | Linux 标识 | 说明 |
|------|------------|------|
| 普通文件 | `-` | 数据文件、可执行文件 |
| 目录 | `d` | 包含其他文件的目录 |
| 符号链接 | `l` | 指向另一个文件 |
| 块设备 | `b` | 磁盘等块设备 |
| 字符设备 | `c` | 终端等字符设备 |
| 管道 | `p` | FIFO 管道 |
| 套接字 | `s` | Unix 域套接字 |

## 2. inode 结构

### 2.1 inode 详解

**面试问题**：什么是 inode？包含哪些信息？

**答案**：

**inode (Index Node)**：存储文件元数据的数据结构，每个文件对应一个 inode。

```
┌─────────────────────────────────────────────────────────┐
│                       inode                              │
├─────────────────────────────────────────────────────────┤
│  inode 编号                                              │
├─────────────────────────────────────────────────────────┤
│  文件类型和权限 (mode)                                   │
├─────────────────────────────────────────────────────────┤
│  硬链接数 (nlink)                                        │
├─────────────────────────────────────────────────────────┤
│  所有者 UID                                              │
├─────────────────────────────────────────────────────────┤
│  所属组 GID                                              │
├─────────────────────────────────────────────────────────┤
│  文件大小 (size)                                         │
├─────────────────────────────────────────────────────────┤
│  时间戳 (atime, mtime, ctime)                            │
├─────────────────────────────────────────────────────────┤
│  数据块指针                                              │
│  ├── 直接指针 (12 个)     → 直接指向数据块               │
│  ├── 一级间接指针 (1 个)  → 指向指针块                   │
│  ├── 二级间接指针 (1 个)  → 指向一级间接块               │
│  └── 三级间接指针 (1 个)  → 指向二级间接块               │
└─────────────────────────────────────────────────────────┘

注意：inode 不包含文件名！文件名存储在目录项中。
```

**数据块寻址**（假设块大小 4KB，指针 4 字节）：

```

二级间接：1024 × 1024 × 4KB = 4GB

三级间接：1024 × 1024 × 1024 × 4KB = 4TB

│    inode     │
├──────────────┤
│ 直接指针 0   │──────────────────────► 数据块 0
│ 直接指针 1   │──────────────────────► 数据块 1
│     ...      │
│ 直接指针 11  │──────────────────────► 数据块 11
├──────────────┤
│ 一级间接     │──► ┌──────────┐
├──────────────┤    │ 指针 0   │──────► 数据块
│ 二级间接     │    │ 指针 1   │──────► 数据块
├──────────────┤    │   ...    │
│ 三级间接     │    │ 指针 1023│──────► 数据块
└──────────────┘    └──────────┘
```

### 2.2 硬链接与软链接

**面试问题**：硬链接和软链接有什么区别？

**答案**：

| 特性 | 硬链接 | 软链接（符号链接） |
|------|--------|-------------------|
| **本质** | 同一 inode 的多个目录项 | 独立文件，存储目标路径 |
| **跨文件系统** | 不可以 | 可以 |
| **链接目录** | 不可以 | 可以 |
| **原文件删除** | 不影响（inode 仍在） | 失效（悬空链接） |
| **inode** | 相同 | 不同 |

```
硬链接：
┌─────────────┐     ┌─────────────┐
│ 目录项 A    │     │ 目录项 B    │
│ 文件名: a   │     │ 文件名: b   │
│ inode: 100  │     │ inode: 100  │
└──────┬──────┘     └──────┬──────┘
       │                   │
       └─────────┬─────────┘
                 ▼
          ┌──────────────┐
          │  inode 100   │
          │  nlink = 2   │
          └──────────────┘
                 │
                 ▼
          ┌──────────────┐
          │   数据块     │
          └──────────────┘


软链接：
┌─────────────┐     ┌─────────────┐
│ 目录项 A    │     │ 目录项 link │
│ 文件名: a   │     │ 文件名: lnk │
│ inode: 100  │     │ inode: 200  │
└──────┬──────┘     └──────┬──────┘
       │                   │
       ▼                   ▼
┌──────────────┐    ┌──────────────┐
│  inode 100   │    │  inode 200   │
└──────────────┘    └──────────────┘
       │                   │
       ▼                   ▼
┌──────────────┐    ┌──────────────┐
│   数据块     │    │  路径: "./a" │
└──────────────┘    └──────────────┘
```

# 创建软链接

## 3. 文件描述符

### 3.1 文件描述符原理

**面试问题**：什么是文件描述符？进程如何管理打开的文件？

**答案**：

**文件描述符 (File Descriptor)**：进程打开文件时获得的非负整数，是文件表项的索引。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                            文件系统三层结构                              │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│   进程 A                    进程 B                                       │
│   ┌─────────────────┐       ┌─────────────────┐                         │
│   │ 文件描述符表    │       │ 文件描述符表    │                         │
│   ├─────────────────┤       ├─────────────────┤                         │
│   │ 0 → stdin       │       │ 0 → stdin       │                         │
│   │ 1 → stdout      │       │ 1 → stdout      │                         │
│   │ 2 → stderr      │       │ 2 → stderr      │                         │
│   │ 3 ──────────────┼───┐   │ 3 ──────────────┼───┐                     │
│   │ 4 ──────────────┼───┼───│ 4 (unused)      │   │                     │
│   └─────────────────┘   │   └─────────────────┘   │                     │
│                         │                         │                     │
├─────────────────────────┼─────────────────────────┼─────────────────────┤
│                         │                         │                     │
│             系统级打开文件表 (Open File Table)                           │
│             ┌───────────────────────────────────┐                       │
│             │ 表项 0                            │                       │
│             │ ├── 文件偏移量 (offset)           │                       │
│             │ ├── 文件状态标志 (flags)          │◄────────────────┐     │
│             │ └── v-node 指针 ─────────────────┼────────┐        │     │
│             ├───────────────────────────────────┤        │        │     │
│             │ 表项 1                            │◄───────┼────────┘     │
│             │ ├── 文件偏移量 (offset)           │        │              │
│             │ ├── 文件状态标志 (flags)          │        │              │
│             │ └── v-node 指针 ─────────────────┼────────┤              │
│             └───────────────────────────────────┘        │              │
│                                                          │              │
├──────────────────────────────────────────────────────────┼──────────────┤
│                                                          │              │
│                    v-node 表 / inode 表                  │              │
│                    ┌───────────────────────────┐         │              │
│                    │ v-node (文件 X)           │◄────────┘              │
│                    │ ├── inode 信息            │                        │
│                    │ └── 文件操作函数指针      │                        │
│                    └───────────────────────────┘                        │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

**三层结构说明**：

| 层次 | 作用域 | 内容 |
|------|--------|------|
| 文件描述符表 | 进程级 | fd → 文件表项的映射 |
| 打开文件表 | 系统级 | 文件偏移量、状态标志 |
| v-node/inode 表 | 系统级 | 文件元数据、操作方法 |

---

### 3.2 文件描述符操作

```c
#include <fcntl.h>
#include <unistd.h>

int main() {
    // 打开文件
    int fd = open("file.txt", O_RDWR | O_CREAT, 0644);
    if (fd < 0) {
        perror("open");
        return 1;
    }

    // 读取
    char buf[1024];
    ssize_t n = read(fd, buf, sizeof(buf));

    // 写入
    const char *msg = "Hello, World!";
    write(fd, msg, strlen(msg));

    // 定位
    lseek(fd, 0, SEEK_SET);  // 移到文件开头

    // 复制文件描述符
    int fd2 = dup(fd);    // 复制到最小可用 fd
    int fd3 = dup2(fd, 10);  // 复制到指定 fd

    // 关闭
    close(fd);
    close(fd2);
    close(fd3);

    return 0;
}
```

**open() 标志**：

| 标志 | 说明 |
|------|------|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |
| `O_CREAT` | 不存在则创建 |
| `O_TRUNC` | 清空文件 |
| `O_APPEND` | 追加模式 |
| `O_NONBLOCK` | 非阻塞 |
| `O_SYNC` | 同步写入 |

### 3.3 标准文件描述符

```c
// 每个进程默认打开的三个文件描述符
#define STDIN_FILENO  0  // 标准输入
#define STDOUT_FILENO 1  // 标准输出
#define STDERR_FILENO 2  // 标准错误

// 重定向示例
int main() {
    // 将标准输出重定向到文件
    int fd = open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    dup2(fd, STDOUT_FILENO);
    close(fd);

    printf("This goes to file\n");  // 输出到 output.txt

    return 0;
}
```

### 4.2 VFS 核心数据结构

```c
// 1. superblock - 文件系统元信息
struct super_block {
    struct list_head s_list;        // 所有 superblock 链表
    dev_t s_dev;                    // 设备标识
    unsigned long s_blocksize;      // 块大小
    struct file_system_type *s_type; // 文件系统类型
    const struct super_operations *s_op;  // 操作方法
    struct dentry *s_root;          // 根目录
    // ...
};

// 2. inode - 文件元数据
struct inode {
    umode_t i_mode;                 // 文件类型和权限
    kuid_t i_uid;                   // 用户 ID
    kgid_t i_gid;                   // 组 ID
    loff_t i_size;                  // 文件大小
    struct timespec64 i_atime;      // 访问时间
    struct timespec64 i_mtime;      // 修改时间
    struct timespec64 i_ctime;      // 状态改变时间
    const struct inode_operations *i_op;   // inode 操作
    const struct file_operations *i_fop;   // 文件操作
    struct super_block *i_sb;       // 所属 superblock
    // ...
};

// 3. dentry - 目录项（路径组件缓存）
struct dentry {
    struct dentry *d_parent;        // 父目录
    struct qstr d_name;             // 文件名
    struct inode *d_inode;          // 关联的 inode
    const struct dentry_operations *d_op;  // 操作方法
    struct super_block *d_sb;       // 所属 superblock
    // ...
};

// 4. file - 打开的文件实例
struct file {
    struct path f_path;             // 路径信息
    struct inode *f_inode;          // 关联的 inode
    const struct file_operations *f_op;  // 文件操作
    loff_t f_pos;                   // 当前偏移量
    unsigned int f_flags;           // 打开标志
    // ...
};
```

### 4.3 dentry 缓存

**面试问题**：什么是 dentry 缓存？有什么作用？

**答案**：

```
路径解析：/home/user/file.txt

没有 dentry 缓存：
每次访问都需要从根目录开始，逐级查找 inode

有 dentry 缓存：
┌─────────────────────────────────────────────────────┐
│                  dentry 缓存                        │
├─────────────────────────────────────────────────────┤
│  "/"      → inode 2   (根目录)                      │
│  "home"   → inode 10  (父: /)                       │
│  "user"   → inode 100 (父: home)                    │
│  "file.txt" → inode 1000 (父: user)                 │
└─────────────────────────────────────────────────────┘

缓存命中：直接获取 inode
缓存未命中：读取磁盘，添加到缓存
```

**dentry 状态**：
- 使用中：d_inode 有效，引用计数 > 0
- 未使用：d_inode 有效，引用计数 = 0（可回收）
- 负状态：d_inode 为空（表示文件不存在，缓存负结果）

## 5. 文件系统布局

### 5.1 ext4 文件系统

**面试问题**：描述 ext4 文件系统的磁盘布局。

**答案**：

```
ext4 磁盘布局：

┌─────────────────────────────────────────────────────────────────┐

每个块组 (Block Group) 结构：

┌─────────────────────────────────────────────────────────────────┐

│ Block │ Descrip │ Bitmap   │ Bitmap   │ Table  │   Blocks      │
│       │ tors    │          │          │        │               │

   │        │          │           │         │          │

```

**Superblock 关键信息**：

```c
struct ext4_super_block {
    __le32 s_inodes_count;      // inode 总数
    __le32 s_blocks_count_lo;   // 块总数
    __le32 s_free_blocks_count_lo;  // 空闲块数
    __le32 s_free_inodes_count;     // 空闲 inode 数
    __le32 s_first_data_block;      // 第一个数据块
    __le32 s_log_block_size;        // 块大小 (1024 << s_log_block_size)
    __le32 s_blocks_per_group;      // 每组块数
    __le32 s_inodes_per_group;      // 每组 inode 数
    // ...
};
```

### 5.2 ext4 特性

| 特性 | 说明 |
|------|------|
| **Extent** | 连续块用一个 extent 描述，减少元数据 |
| **延迟分配** | 写入缓存时不立即分配块，提高连续性 |
| **日志** | 崩溃后快速恢复 |
| **大文件** | 支持 16TB 单文件，1EB 文件系统 |
| **多块分配** | 一次分配多个连续块 |

**Extent 结构**：

```
传统 ext3 块映射（inode 中存储块号）：
文件: [块1] [块2] [块3] [块4] [块5] [块6] ...
开销: 每个块需要 4 字节指针

ext4 Extent：
┌─────────────────────────────────────────┐
│ extent: 起始块 = 100, 长度 = 1000       │
└─────────────────────────────────────────┘
代表: 块 100-1099 连续存储
开销: 12 字节描述 1000 个块
```

## 6. 文件系统缓存

### 6.1 Page Cache

**面试问题**：什么是 Page Cache？有什么作用？

**答案**：

**Page Cache（页缓存）**：内核将磁盘数据缓存在内存中。

```
读操作流程：

read() ──► Page Cache 查找
              │
        ┌─────┴─────┐
        │  命中？   │
        └─────┬─────┘
          ╱       ╲
        是         否
        │           │
        ▼           ▼
   返回数据    从磁盘读取
                    │
                    ▼
              加入 Page Cache
                    │
                    ▼
               返回数据


写操作流程：

write() ──► 写入 Page Cache
                 │
                 ▼
           标记为脏页
                 │
                 ▼
        ┌────────┴────────┐
        │   立即写回？    │
        └────────┬────────┘
             ╱       ╲
          O_SYNC     普通写入
           │           │
           ▼           ▼
        立即写盘    延迟写回
                   (pdflush)
```

### 6.2 Buffer Cache

**面试问题**：Page Cache 和 Buffer Cache 的区别？

**答案**：

| 特性 | Page Cache | Buffer Cache |

| **使用场景** | 文件读写 | 块设备直接访问 |

## 7. 日志文件系统

### 7.1 日志原理

**面试问题**：什么是日志文件系统？解决什么问题？

**答案**：

**问题**：系统崩溃可能导致文件系统不一致

```
传统问题：删除文件操作

1. 释放数据块
2. 释放 inode
3. 更新目录项

如果在步骤 2 后崩溃：
- 数据块已释放
- inode 未释放 → 成为孤儿 inode
- 需要 fsck 全盘扫描修复（可能很慢）
```

**日志解决方案**：

```
日志文件系统操作流程：

┌─────────────────────────────────────────────────────┐
│  1. 记录日志（Journal）                             │
│     将要修改的操作写入日志区域                       │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│  2. 提交日志（Commit）                              │
│     确保日志完整写入                                 │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│  3. 执行操作（Checkpoint）                          │
│     实际修改文件系统                                 │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│  4. 清除日志                                        │
│     操作完成后删除日志记录                          │
└─────────────────────────────────────────────────────┘

崩溃恢复：
- 检查日志区域
- 已提交的日志：重放操作
- 未提交的日志：丢弃
- 恢复时间：秒级（vs fsck 的分钟/小时级）
```

---

### 7.2 日志模式

| 模式 | 记录内容 | 性能 | 安全性 |
|------|----------|------|--------|
| **journal** | 元数据 + 数据 | 最慢 | 最高 |
| **ordered** | 仅元数据（先写数据） | 中等 | 中等 |
| **writeback** | 仅元数据 | 最快 | 最低 |

```bash
# 查看挂载选项
mount | grep ext4

# 以 ordered 模式挂载
mount -o data=ordered /dev/sda1 /mnt
```

## 8. 面试常见问题

### 8.1 高频问题汇总

**Q1：inode 是什么？存储什么信息？**
- 存储文件元数据：类型、权限、大小、时间戳、数据块指针
- 不包含文件名（文件名在目录项中）

**Q2：硬链接和软链接的区别？**
- 硬链接：同一 inode，不能跨文件系统，不能链接目录
- 软链接：独立 inode，存储路径，可跨文件系统，可链接目录

**Q3：文件描述符是什么？**
- 进程打开文件的句柄（非负整数）
- 索引到系统打开文件表

**Q4：VFS 的作用？**
- 统一不同文件系统的接口
- 提供 superblock、inode、dentry、file 抽象

**Q5：Page Cache 和 Buffer Cache？**
- 现代 Linux 已统一
- Page Cache 缓存文件数据页
- Buffer Cache 缓存磁盘块（现在作为 Page Cache 的一部分）

**Q6：日志文件系统的优势？**
- 快速崩溃恢复（秒级）
- 保证文件系统一致性
- 三种模式：journal、ordered、writeback

**Q7：一个进程能打开多少文件？**
- 软限制：通常 1024（可调整）
- 硬限制：受 `/proc/sys/fs/file-max` 限制
- `ulimit -n` 查看和修改
