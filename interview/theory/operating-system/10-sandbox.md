 # 沙箱安全模型深入解析

沙箱（Sandbox）是现代软件安全的核心机制，广泛应用于浏览器、容器、移动端等场景。

---

## 1. 沙箱基础概念

### 1.1 什么是沙箱

```
┌─────────────────────────────────────────────────────────────┐
│                      沙箱定义                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  沙箱是一种安全机制，用于隔离运行中的程序，限制其对系统资源   │
│  的访问，即使程序被攻破，也无法影响宿主系统和其他程序。       │
│                                                             │
│  核心思想：                                                  │
│  ─────────────────────────────────────────────────────────  │
│  1. 最小权限原则（Principle of Least Privilege）            │
│     程序只拥有完成任务所需的最小权限                         │
│                                                             │
│  2. 纵深防御（Defense in Depth）                             │
│     多层安全机制，单点突破不会导致完全失陷                   │
│                                                             │
│  3. 隔离（Isolation）                                        │
│     程序之间相互隔离，一个被攻破不影响其他                   │
│                                                             │
│  类比：                                                      │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  沙箱就像儿童游乐场的沙坑：                            │  │
│  │  • 孩子可以在沙坑里自由玩耍（程序可以执行）            │  │
│  │  • 沙子不会弄到沙坑外面（不能影响系统）                │  │
│  │  • 沙坑有边界限制活动范围（权限受限）                  │  │
│  └───────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 进程隔离

```

│                      进程隔离                                │
├─────────────────────────────────────────────────────────────┤
```

```cpp
// 创建新命名空间的示例
#define _GNU_SOURCE
#include <sched.h>
#include <unistd.h>
#include <sys/wait.h>

int child_func(void* arg) {
    // 在新的命名空间中执行
    printf("Child PID in new namespace: %d\n", getpid());  // 输出 1
    execl("/bin/sh", "sh", NULL);
    return 0;
}

int main() {
    char stack[1024 * 1024];

    // 创建新进程，带有新的 PID、UTS、Mount 命名空间
    int flags = CLONE_NEWPID | CLONE_NEWUTS | CLONE_NEWNS | SIGCHLD;

    pid_t pid = clone(child_func, stack + sizeof(stack), flags, NULL);

    waitpid(pid, NULL, 0);
    return 0;
}
```

### 2.3 seccomp（系统调用过滤）

```
┌─────────────────────────────────────────────────────────────┐
│                      seccomp 机制                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  seccomp (Secure Computing Mode) - Linux 系统调用过滤器     │
│                                                             │
│  工作原理：                                                  │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  应用程序                                            │   │
│  │      ↓ 系统调用                                      │   │
│  │  ┌─────────────────────────────────────────────┐    │   │
│  │  │           seccomp-bpf 过滤器                 │    │   │
│  │  │  ┌─────────────────────────────────────┐    │    │   │
│  │  │  │  规则：                              │    │    │   │
│  │  │  │  • read/write → 允许                │    │    │   │
│  │  │  │  • open → 允许                      │    │    │   │
│  │  │  │  • execve → 拒绝                    │    │    │   │
│  │  │  │  • ptrace → 拒绝                    │    │    │   │
│  │  │  │  • socket → 拒绝                    │    │    │   │
│  │  │  └─────────────────────────────────────┘    │    │   │
│  │  └─────────────────────────────────────────────┘    │   │
│  │      ↓ 允许的调用                                    │   │
│  │  内核                                                │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  两种模式：                                                  │
│  1. SECCOMP_MODE_STRICT  - 只允许 read/write/exit/sigreturn │
│  2. SECCOMP_MODE_FILTER  - 自定义 BPF 过滤规则              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```cpp
// seccomp 示例：只允许 read、write、exit
#include <linux/seccomp.h>
#include <linux/filter.h>
#include <linux/audit.h>
#include <sys/prctl.h>
#include <sys/syscall.h>

void setup_seccomp() {
    struct sock_filter filter[] = {
        // 加载系统调用号
        BPF_STMT(BPF_LD | BPF_W | BPF_ABS,
                 offsetof(struct seccomp_data, nr)),

        // 允许 read (syscall 0)
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_read, 0, 1),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),

        // 允许 write (syscall 1)
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_write, 0, 1),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),

        // 允许 exit_group
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_exit_group, 0, 1),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),

        // 其他系统调用：杀死进程
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL),
    };

    struct sock_fprog prog = {
        .len = sizeof(filter) / sizeof(filter[0]),
        .filter = filter,
    };

    // 禁止获取新权限
    prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);

    // 应用 seccomp 过滤器
    prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog);
}
```

### 2.5 chroot 与 pivot_root

```
┌─────────────────────────────────────────────────────────────┐
│                  文件系统隔离                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  chroot - 改变进程的根目录                                   │
│  ─────────────────────────────────────────────────────────  │
│                                                             │
│  原始文件系统：           chroot 后：                        │
│  /                        /sandbox/rootfs → /               │
│  ├── bin                  ├── bin                           │
│  ├── etc                  ├── etc                           │
│  ├── home                 ├── lib                           │
│  ├── sandbox              └── usr                           │
│  │   └── rootfs                                             │
│  │       ├── bin          进程无法访问 /sandbox 之外的文件   │
│  │       ├── etc                                            │
│  │       └── lib                                            │
│  └── ...                                                    │
│                                                             │
│  chroot 的局限性：                                           │
│  • root 用户可以逃逸（使用 fchdir + chroot 组合）           │
│  • 不隔离进程、网络等资源                                   │
│  • 需要复制完整的运行环境                                   │
│                                                             │
│  pivot_root - 更安全的根文件系统切换                        │
│  ─────────────────────────────────────────────────────────  │
│  • 用于容器启动                                             │
│  • 彻底切换根文件系统                                       │
│  • 配合 mount namespace 使用                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```cpp
// chroot 示例
#include <unistd.h>

void setup_chroot(const char* new_root) {
    // 切换根目录
    if (chroot(new_root) != 0) {
        perror("chroot");
        exit(1);
    }

    // 切换工作目录
    if (chdir("/") != 0) {
        perror("chdir");
        exit(1);
    }
}

// 更安全的 pivot_root（用于容器）
void setup_pivot_root(const char* new_root) {
    // 1. 确保 new_root 是挂载点
    mount(new_root, new_root, NULL, MS_BIND | MS_REC, NULL);

    // 2. 创建 old_root 目录
    char old_root[PATH_MAX];
    snprintf(old_root, sizeof(old_root), "%s/.old_root", new_root);
    mkdir(old_root, 0755);

    // 3. 执行 pivot_root
    syscall(SYS_pivot_root, new_root, old_root);

    // 4. 切换到新根目录
    chdir("/");

    // 5. 卸载旧根目录
    umount2("/.old_root", MNT_DETACH);
    rmdir("/.old_root");
}
```

## 3. 浏览器沙箱（Chromium）

### 5.2 Windows 沙箱代码示例

```cpp
#include <windows.h>
#include <sddl.h>

// 创建低完整性级别进程
BOOL CreateLowIntegrityProcess(LPCWSTR app) {
    HANDLE hToken, hNewToken;
    STARTUPINFOW si = { sizeof(si) };
    PROCESS_INFORMATION pi;

    // 1. 获取当前进程令牌
    OpenProcessToken(GetCurrentProcess(),
                     TOKEN_DUPLICATE | TOKEN_QUERY | TOKEN_ADJUST_DEFAULT,
                     &hToken);

    // 2. 复制令牌
    DuplicateTokenEx(hToken, 0, NULL, SecurityImpersonation,
                     TokenPrimary, &hNewToken);

    // 3. 设置低完整性级别
    PSID pLowIntegritySid;
    ConvertStringSidToSidW(L"S-1-16-4096", &pLowIntegritySid);

    TOKEN_MANDATORY_LABEL tml = { 0 };
    tml.Label.Attributes = SE_GROUP_INTEGRITY;
    tml.Label.Sid = pLowIntegritySid;

    SetTokenInformation(hNewToken, TokenIntegrityLevel,
                        &tml, sizeof(tml) + GetLengthSid(pLowIntegritySid));

    // 4. 使用受限令牌创建进程
    BOOL result = CreateProcessAsUserW(
        hNewToken, app, NULL, NULL, NULL, FALSE,
        CREATE_NEW_CONSOLE, NULL, NULL, &si, &pi
    );

    LocalFree(pLowIntegritySid);
    CloseHandle(hNewToken);
    CloseHandle(hToken);

    return result;
}

// 创建带 Job Object 限制的进程
BOOL CreateSandboxedProcess(LPCWSTR app) {
    // 1. 创建 Job Object
    HANDLE hJob = CreateJobObjectW(NULL, NULL);

    // 2. 设置限制
    JOBOBJECT_EXTENDED_LIMIT_INFORMATION jobInfo = { 0 };
    jobInfo.BasicLimitInformation.LimitFlags =
        JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE |    // 关闭 Job 时杀死所有进程
        JOB_OBJECT_LIMIT_DIE_ON_UNHANDLED_EXCEPTION |
        JOB_OBJECT_LIMIT_ACTIVE_PROCESS;         // 限制进程数

    jobInfo.BasicLimitInformation.ActiveProcessLimit = 1;

    SetInformationJobObject(hJob, JobObjectExtendedLimitInformation,
                            &jobInfo, sizeof(jobInfo));

    // 3. 设置 UI 限制
    JOBOBJECT_BASIC_UI_RESTRICTIONS uiRestrictions = { 0 };
    uiRestrictions.UIRestrictionsClass =
        JOB_OBJECT_UILIMIT_DESKTOP |
        JOB_OBJECT_UILIMIT_DISPLAYSETTINGS |
        JOB_OBJECT_UILIMIT_EXITWINDOWS |
        JOB_OBJECT_UILIMIT_GLOBALATOMS |
        JOB_OBJECT_UILIMIT_HANDLES |
        JOB_OBJECT_UILIMIT_READCLIPBOARD |
        JOB_OBJECT_UILIMIT_SYSTEMPARAMETERS |
        JOB_OBJECT_UILIMIT_WRITECLIPBOARD;

    SetInformationJobObject(hJob, JobObjectBasicUIRestrictions,
                            &uiRestrictions, sizeof(uiRestrictions));

    // 4. 创建进程并加入 Job
    STARTUPINFOW si = { sizeof(si) };
    PROCESS_INFORMATION pi;

    CreateProcessW(app, NULL, NULL, NULL, FALSE,
                   CREATE_SUSPENDED, NULL, NULL, &si, &pi);

    AssignProcessToJobObject(hJob, pi.hProcess);
    ResumeThread(pi.hThread);

    return TRUE;
}
```

### 7.2 C++ 插件沙箱实现

```cpp
// === 插件沙箱框架示例 ===

#include <sys/prctl.h>
#include <linux/seccomp.h>
#include <unistd.h>

// 插件接口
class IPlugin {
public:
    virtual ~IPlugin() = default;
    virtual std::string getName() = 0;
    virtual void execute(const PluginContext& ctx) = 0;
};

// 沙箱配置
struct SandboxConfig {
    bool allow_network = false;
    bool allow_filesystem = false;
    size_t memory_limit = 64 * 1024 * 1024;  // 64MB
    size_t cpu_time_limit = 5;  // 5 seconds
    std::vector<std::string> allowed_paths;
};

// 沙箱管理器
class PluginSandbox {
public:
    explicit PluginSandbox(const SandboxConfig& config)
        : config_(config) {}

    pid_t launchPlugin(const std::string& plugin_path) {
        int pipefd[2];
        pipe(pipefd);  // 用于 IPC

        pid_t pid = fork();
        if (pid == 0) {
            // 子进程：设置沙箱并加载插件
            close(pipefd[0]);
            setupSandbox();
            loadAndRunPlugin(plugin_path, pipefd[1]);
            exit(0);
        }

        // 父进程
        close(pipefd[1]);
        plugin_pipes_[pid] = pipefd[0];
        return pid;
    }

private:
    void setupSandbox() {
        // 1. 设置资源限制
        setResourceLimits();

        // 2. 设置 seccomp 过滤
        setupSeccomp();

        // 3. 设置文件系统隔离
        if (!config_.allow_filesystem) {
            setupFilesystemIsolation();
        }

        // 4. 删除不必要的 capabilities
        dropCapabilities();

        // 5. 设置 no_new_privs
        prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);
    }

    void setResourceLimits() {
        struct rlimit rl;

        // 内存限制
        rl.rlim_cur = rl.rlim_max = config_.memory_limit;
        setrlimit(RLIMIT_AS, &rl);

        // CPU 时间限制
        rl.rlim_cur = rl.rlim_max = config_.cpu_time_limit;
        setrlimit(RLIMIT_CPU, &rl);

        // 禁止创建子进程
        rl.rlim_cur = rl.rlim_max = 0;
        setrlimit(RLIMIT_NPROC, &rl);

        // 禁止创建文件
        if (!config_.allow_filesystem) {
            rl.rlim_cur = rl.rlim_max = 0;
            setrlimit(RLIMIT_FSIZE, &rl);
        }
    }

    void setupSeccomp() {
        // 使用 libseccomp 设置白名单
        scmp_filter_ctx ctx = seccomp_init(SCMP_ACT_KILL);

        // 允许的系统调用
        seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(read), 0);
        seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(write), 0);
        seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(mmap), 0);
        seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(munmap), 0);
        seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(exit_group), 0);
        seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(brk), 0);

        if (config_.allow_network) {
            seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(socket), 0);
            seccomp_rule_add(ctx, SCMP_ACT_ALLOW, SCMP_SYS(connect), 0);
        }

        seccomp_load(ctx);
        seccomp_release(ctx);
    }

    void setupFilesystemIsolation() {
        // chroot 到空目录或只读目录
        if (chroot("/var/sandbox/empty") != 0) {
            exit(1);
        }
        chdir("/");
    }

    void dropCapabilities() {
        cap_t caps = cap_init();
        cap_set_proc(caps);
        cap_free(caps);
    }

    SandboxConfig config_;
    std::map<pid_t, int> plugin_pipes_;
};

// 安全的插件 API
class PluginAPI {
public:
    // 所有操作都通过 IPC 发送到主进程执行
    std::string readFile(const std::string& path) {
        if (!isPathAllowed(path)) {
            throw PermissionDenied("File access not allowed: " + path);
        }
        return sendRequest({"read_file", path});
    }

    void log(const std::string& message) {
        sendRequest({"log", message});
    }

    // 网络请求需要权限
    std::string httpGet(const std::string& url) {
        if (!hasCapability(CAP_NETWORK)) {
            throw PermissionDenied("Network access not allowed");
        }
        return sendRequest({"http_get", url});
    }

private:
    std::string sendRequest(const std::vector<std::string>& req);
    bool isPathAllowed(const std::string& path);
    bool hasCapability(int cap);
};
```

## 8. 面试常见问题

### Q1: 什么是沙箱？核心原理是什么？

```
沙箱（Sandbox）是一种安全隔离机制，用于限制程序对系统资源的访问。

核心原理：
1. 最小权限原则
   程序只拥有完成任务所需的最小权限

2. 隔离
   进程间相互隔离，一个被攻破不影响其他

3. 纵深防御
   多层安全机制，单点突破不会导致完全失陷

实现技术（Linux）：
• 进程隔离 - 独立地址空间
• Namespace - 资源视图隔离
• seccomp - 系统调用过滤
• Capabilities - 细粒度权限控制
• cgroups - 资源使用限制
• chroot/pivot_root - 文件系统隔离
```

### Q2: 浏览器沙箱是如何实现的？

```
以 Chromium 为例：

多进程架构：
• Browser 进程 - 高权限，处理 UI/网络/文件
• Renderer 进程 - 沙箱内，处理 HTML/JS/渲染
• GPU 进程 - 部分沙箱
• 插件进程 - 沙箱内

Renderer 进程沙箱限制：
• 无直接文件系统访问
• 无网络权限（通过 Browser IPC）
• 严格的系统调用过滤
• 最低权限级别运行

逃逸防护：
• Site Isolation - 每个站点独立进程
• seccomp-bpf - 系统调用白名单
• 用户命名空间 - 容器化隔离
• IPC 严格验证 - 防止 Browser 被欺骗

即使 Renderer 被 RCE 攻破，攻击者仍需：
1. 绕过 seccomp（需要内核漏洞）
2. 或找到 IPC 漏洞欺骗 Browser
```

### Q3: Docker 容器是真正的沙箱吗？

```
Docker 是"软隔离"，不是完全的沙箱。

Docker 隔离机制：
• Namespace - 进程/网络/文件系统隔离
• cgroups - 资源限制
• seccomp - 系统调用过滤
• Capabilities 削减

局限性：
• 共享宿主机内核 - 内核漏洞可导致逃逸
• 默认配置不够安全 - 需要加固
• 容器内 root ≈ 宿主机 root（无 user namespace 时）

安全建议：
• 启用 User Namespace
• 使用非 root 用户运行
• 只读文件系统
• 使用 seccomp 配置文件
• 考虑 gVisor/Kata 增强隔离

对于不可信代码：
• 使用虚拟机（KVM/Xen）
• 或使用 gVisor（用户态内核）
• 或 Kata Containers（轻量级 VM）
```

### Q4: seccomp 是什么？如何工作？

```
seccomp（Secure Computing Mode）是 Linux 的系统调用过滤机制。

工作原理：
1. 进程设置 BPF（伯克利包过滤）规则
2. 每次系统调用前，内核检查 BPF 规则
3. 根据规则决定：允许/拒绝/杀死进程/返回错误

两种模式：
• STRICT - 只允许 read/write/exit/sigreturn
• FILTER - 自定义 BPF 规则，可精细控制

使用场景：
• 浏览器沙箱（Chromium）
• 容器运行时（Docker）
• 在线评测系统
• 任何需要限制系统调用的场景

优点：
• 内核级过滤，无法绕过
• 性能开销小
• 灵活的规则配置

缺点：
• 规则复杂时难以维护
• 需要了解所有必要的系统调用
```

### Q5: 如何设计一个安全的插件系统？

```
设计原则：
1. 进程隔离 - 插件在独立进程运行
2. 最小权限 - 只授予必要权限
3. 能力声明 - 插件声明所需权限
4. API 网关 - 所有系统操作通过安全 API
5. 资源限制 - CPU/内存/时间限制

架构：
┌─────────────────┐
│    Host 进程     │ ← 高权限，管理插件
│    (全信任)      │
└────────┬────────┘
         │ IPC（验证所有消息）
    ┌────┴────┐
    ↓         ↓
┌───────┐ ┌───────┐
│Plugin │ │Plugin │  ← 沙箱进程
│(沙箱) │ │(沙箱) │     每个插件独立
└───────┘ └───────┘

沙箱措施：
• seccomp 系统调用过滤
• 删除 capabilities
• 资源限制（rlimit/cgroups）
• 文件系统隔离（chroot）
• 网络限制（namespace/seccomp）

安全 IPC：
• 验证所有消息格式
• 检查权限再执行操作
• 限制 IPC 消息频率
• 审计日志
```

### Q6: Namespace 和 cgroups 有什么区别？

```
Namespace（命名空间）：
• 功能：隔离资源的可见性/视图
• 每种资源有独立命名空间：PID/Net/Mount/User/UTS/IPC
• 效果：进程看不到其他命名空间的资源
• 类比：每个容器有自己的"世界观"

cgroups（控制组）：
• 功能：限制资源的使用量
• 可控制：CPU/内存/磁盘 IO/进程数等
• 效果：进程不能使用超过配额的资源
• 类比：给每个容器分配"配额"

对比：
┌─────────────────────────────────────────────┐
│  Namespace       cgroups                    │
├─────────────────────────────────────────────┤
│  "看到什么"       "能用多少"                 │
│  隔离视图         限制配额                   │
│  PID 1 in 容器   最多用 512MB 内存          │
│  独立网络栈       CPU 份额 50%               │
└─────────────────────────────────────────────┘

容器 = Namespace + cgroups + 其他安全机制
```

### Q7: 沙箱逃逸有哪些常见方式？如何防护？

```
常见逃逸方式：

1. 内核漏洞
   • 利用内核漏洞提权
   • 防护：内核加固、最小化系统调用、grsecurity

2. 系统调用过滤绕过
   • 利用未过滤的系统调用
   • 防护：白名单策略、严格参数检查

3. 配置错误
   • 过度授权、危险挂载
   • 防护：安全审计、最小权限配置

4. 共享资源漏洞
   • 利用共享内存、信号等
   • 防护：最小化共享资源

5. 侧信道攻击
   • Spectre/Meltdown
   • 防护：Site Isolation、进程隔离

6. IPC 漏洞
   • 欺骗高权限进程执行操作
   • 防护：严格的 IPC 消息验证

防护策略：
• 多层防御（不依赖单一机制）
• 最小权限原则
• 及时更新安全补丁
• 使用更强隔离（VM/gVisor）
```

### Q8: Windows 和 Linux 沙箱机制有什么区别？

```
Linux 沙箱机制：
• Namespace - 资源隔离
• cgroups - 资源限制
• seccomp-bpf - 系统调用过滤
• Capabilities - 细粒度权限
• SELinux/AppArmor - MAC
• chroot/pivot_root - 文件系统隔离

Windows 沙箱机制：
• Integrity Levels - 完整性级别
• Restricted Tokens - 受限令牌
• Job Objects - 进程组限制
• Desktop/WindowStation - UI 隔离
• AppContainer - 最严格沙箱（Win8+）
• Virtualization-Based Security - 虚拟化隔离

对比：
┌─────────────────────────────────────────────────┐
│  功能              Linux           Windows      │
├─────────────────────────────────────────────────┤
│  系统调用过滤       seccomp         NtFilter    │
│  资源隔离          Namespace       Job Object   │
│  资源限制          cgroups         Job Object   │
│  权限控制          Capabilities    Token+ACL    │
│  MAC              SELinux         Integrity    │
│  最强沙箱          User NS+seccomp AppContainer│
└─────────────────────────────────────────────────┘

Linux 更灵活，Windows 更整合。
```
