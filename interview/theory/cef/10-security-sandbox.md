# 10 - 安全与沙箱

## 核心概念

嵌入 Chromium = 引入 **浏览器攻击面**。CEF 应用要按「迷你浏览器产品」做安全设计，而不是普通控件。

---

## 沙箱与权限

- 生产保持沙箱开启（除非有文档级理由）  
- 危险：随意 `--no-sandbox`、过度暴露 JS 桥、允许 `file://` 读任意路径  
- Windows：理解沙箱对权限与调试的影响  

---

## Web 内容安全

| 措施 | 作用 |
|------|------|
| 只加载可信源 | 内置包、HTTPS 白名单 |
| CSP | 减 XSS 与注入脚本 |
| 自定义 Scheme | 本地资源可控 |
| 禁用或限制插件/危险功能 | 按设置与 command line |
| 证书错误策略 | 勿对所有错误一键忽略 |

## 升级与 CVE

过时 Chromium = 已知 CVE。流程：跟踪 CEF 发布 → 回归嵌窗/桥/OSR → 发布。

---

## 常见面试题

**Q1：CEF 安全和普通 Win32 程序差在哪？**  
答：多了解析器与 Web 攻击面；要沙箱、内容源控制、桥收敛、跟补丁。

**Q2：能否为了方便关沙箱？**  
答：调试可；生产默认否，需安全评审。
