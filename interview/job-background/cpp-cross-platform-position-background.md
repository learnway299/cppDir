## 常见面试考察与解答

1. 问：`unique_ptr`、`shared_ptr`、`weak_ptr` 怎么选？  
答：默认 `unique_ptr`；需要共享生命周期用 `shared_ptr`；只观察不持有、或打破循环引用用 `weak_ptr`。

2. 问：`new` 出来的对象在函数返回后会自动释放吗？  
答：不会。函数内局部指针会销毁，但堆对象不会，需显式释放或交给智能指针管理。

3. 问：`std::move` 会移动对象吗？  
答：`std::move` 只做类型转换（转成右值）；真正“移动资源”由移动构造/移动赋值实现决定。

4. 问：指针传参和引用传参性能差别大吗？  
答：通常差异很小，都接近传地址。主要差异是语义：指针可空可改指向；引用不可空且不重绑定。

5. 问：`x++` 和 `++x` 区别是什么？  
答：都让 `x` 自增；`++x` 返回新值（左值语义），`x++` 返回旧值副本（临时值）。

6. 问：Windows 消息循环为什么重要？  
答：GUI 线程通过消息泵驱动事件分发和窗口响应；阻塞消息循环会导致界面卡死、无响应。

7. 问：Win32 和 macOS 跨平台开发常见差异有哪些？  
答：窗口系统、线程模型细节、文件路径与编码、动态库加载、信号/异常机制、打包发布流程都存在差异。

8. 问：崩溃 dump 分析的一般流程？  
答：先符号化，再看异常类型和 fault address，然后看崩溃线程栈与寄存器，最后回溯触发路径与资源状态。

9. 问：WinDbg 排查崩溃你会先看什么？  
答：先 `!analyze -v` 获取结论，再看异常线程调用栈、模块符号是否匹配、关键对象内存状态。

10. 问：多线程里最常见问题是什么？  
答：数据竞争、死锁、锁顺序不一致、生命周期竞态（对象已释放但线程仍访问）。

11. 问：如何做 SQLite 性能优化？  
答：优先索引设计和 SQL 改写，其次事务批量提交、预编译语句、WAL 模式、减少磁盘同步频率。

12. 问：Node.js 原生模块（N-API）价值是什么？  
答：把性能敏感或已有 C/C++ 能力复用到 JS 层，兼顾性能与跨版本 ABI 稳定性。

13. 问：Electron 客户端常见性能瓶颈在哪？  
答：主进程阻塞、渲染进程脚本与重绘压力、进程间通信频繁、内存常驻过高。

14. 问：你如何做“稳定性治理”？  
答：建立崩溃捕获和符号化流水线、按模块聚类崩溃、设置回归门禁、推动问题闭环和复盘。

15. 问：如何向面试官展示“可落地能力”？  
答：给出具体案例：问题背景、定位路径、关键指标、改动方案、上线后数据对比与复盘结论。

## DuiLib 与 Qt 对比（面试补充）

### 1. 定位差异
- `DuiLib`：Windows 平台轻量 UI 框架，核心围绕 Win32 消息机制和自绘。
- `Qt`：跨平台应用开发框架，包含 UI、网络、线程、数据库等完整能力。

### 2. 平台支持
- `DuiLib`：主要面向 Windows。
- `Qt`：支持 Windows/macOS/Linux（以及移动端扩展）。

### 3. 工程能力与生态
- `DuiLib`：框架体量小，定制灵活，但生态和官方工具链相对有限。
- `Qt`：生态成熟，文档完善，工具链（Designer/QML/Creator）和社区更完整。

### 4. 开发效率
- `DuiLib`：对 Win32 基础要求较高，很多交互细节需手工处理。
- `Qt`：信号槽机制与高层抽象多，复杂业务界面开发效率通常更高。

### 5. 性能与包体
- `DuiLib`：通常更轻量，启动和包体表现有优势（纯 Windows 场景）。
- `Qt`：功能更全，包体和依赖相对更重，但可换来更强的通用能力。

### 6. 面试回答建议（如何选型）
- 仅 Windows 桌面端、强调轻量和 Win32 深度定制：可优先 `DuiLib`。
- 需要跨平台统一代码、长期维护和团队协作效率：优先 `Qt`。
- 结论应结合业务目标：平台范围、团队能力、发布周期、维护成本。
