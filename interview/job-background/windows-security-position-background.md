# Windows 安全方向岗位背景（C/C++/Golang）

## 岗位背景（基于截图）
- 计算机相关专业背景。
- 精通 C/C++/Golang 一种或多种语言。
- 2 年及以上开发经验，具备常见数据结构与算法基础。
- 精通 Windows 操作系统，熟悉 Windows 安全机制与常见安全防护方案。
- 学习能力强，具备分析与解决问题能力。
- 具备团队协作意识与主动性。

## 常见面试考察与解答

1. 问：为什么这个岗位常要求 C/C++？
答：Windows 底层接口、性能敏感模块、安全产品核心能力通常依赖原生开发；C/C++便于控制内存、调用系统 API、实现高性能组件。

2. 问：Golang 在安全产品里通常做什么？
答：常用于控制面、服务编排、任务调度、日志与策略分发；与 C/C++ 底层模块通过 RPC、管道或 SDK 对接。

3. 问：Windows 安全机制中最核心的权限模型是什么？
答：基于 Access Token + SID + ACL 的访问控制模型。进程/线程携带 Token，访问对象时由系统依据 ACL 判定是否授权。

4. 问：UAC 的作用是什么？
答：降低默认高权限运行风险。管理员账户默认以受限令牌运行，提权操作需显式同意，减少恶意代码直接获得高权限的概率。

5. 问：完整性级别（Integrity Level）有什么意义？
答：用于强制完整性控制（MIC）。低完整性进程通常不能写高完整性对象，可降低浏览器等高风险进程对系统的破坏面。

6. 问：常见内存安全防护机制有哪些？
答：DEP（数据执行保护）、ASLR（地址随机化）、CFG（控制流保护）、GS（栈保护）等；它们共同提升漏洞利用难度。

7. 问：什么是最小权限原则，如何在工程里落地？
答：组件只申请必需权限，不默认管理员运行；按功能拆分权限边界，敏感操作隔离到受控进程/服务并做审计。

8. 问：用户态和内核态安全边界为什么关键？
答：内核态失陷影响全系统。安全设计应尽量将复杂逻辑留在用户态，内核模块最小化，接口严格校验输入。

9. 问：如何理解“防护”与“检测”的区别？
答：防护是阻断攻击路径（预防）；检测是发现异常行为并告警（响应）。安全产品通常需要“预防 + 检测 + 处置”闭环。

10. 问：常见安全防护方案有哪些？
答：主机加固（补丁、基线）、应用白名单、行为监控、漏洞利用缓解、沙箱隔离、日志审计、EDR/告警联动。

11. 问：如果发现进程 CPU 飙升且疑似恶意注入，你会怎么排查？
答：先保留现场（进程信息、模块、句柄、网络连接），再定位可疑线程与模块来源，结合调用栈/内存区域判断注入方式，最后给出处置建议。

12. 问：数据结构与算法在该岗位中的真实价值是什么？
答：用于规则匹配、行为关联、日志索引、调度优化、内存效率优化；不仅是面试题，直接影响检测性能和误报率。

13. 问：多线程安全开发最常见问题？
答：数据竞争、锁顺序不一致导致死锁、生命周期竞态（对象已释放仍被访问）。应通过明确所有权和同步策略避免。

14. 问：如何平衡“安全强度”和“业务可用性”？
答：按风险分级策略落地，默认安全但可回退；先灰度再全量，配套误报处理与白名单流程，持续迭代规则质量。

15. 问：该岗位如何考察软素质（学习/协作）？
答：常通过案例追问：你如何快速补齐陌生领域、如何与产品和测试协同推进、如何在冲突中达成可执行方案。
## Windows 安全机制（由浅入深）与面试考察

16. 问：Windows 安全体系最基础的目标是什么？
答：核心是 CIA（机密性、完整性、可用性）+ 可审计性。落地到系统层就是“谁可以访问什么对象、在什么条件下访问、访问后能否追踪”。

17. 问：Windows 对“主体”和“客体”是怎么建模的？
答：主体通常是进程/线程（携带 Access Token），客体是文件、进程、注册表项、命名管道、事件等内核对象。系统在对象访问路径上做统一鉴权。

18. 问：Access Token、SID、ACL、ACE 分别是什么关系？
答：Token 里有用户 SID、组 SID、权限（Privileges）、完整性级别等；对象有安全描述符（DACL/SACL）；DACL 由 ACE 构成。访问检查本质是“Token 对比 ACL 规则”后得到 Allow/Deny。

19. 问：UAC 与“管理员账号”到底是什么关系？
答：管理员账号默认也以受限令牌运行；只有显式提权才切到高权限令牌。它不是边界级防护，但能显著减少“默认高权限运行”的攻击面。

20. 问：完整性级别（Low/Medium/High/System）在实战中的意义？
答：这是 MIC（Mandatory Integrity Control）机制。典型策略是“低完整性不能写高完整性对象”，可限制浏览器沙箱逃逸后直接篡改系统关键资源。

21. 问：LSA/凭据保护链路为什么是高频考点？
答：因为认证与凭据是横向移动核心。常考点包括 LSASS 保护、Credential Guard、NTLM/Kerberos 基本流程，以及如何降低明文/可重放凭据暴露面。

22. 问：常见漏洞缓解机制（DEP/ASLR/CFG/CET）各解决什么问题？
答：DEP 限制数据页执行，ASLR 增加地址预测难度，CFG 限制非法间接调用目标，CET 提供硬件级控制流保护（如影子栈）。它们叠加后能明显提高利用链复杂度，但不能替代代码无漏洞。

23. 问：内核层的 PatchGuard、VBS、HVCI 分别偏向什么能力？
答：PatchGuard 防止关键内核结构被非法篡改；VBS 用虚拟化隔离高价值安全组件；HVCI 用硬件虚拟化增强代码完整性校验。面试常追问性能开销与兼容性取舍。

24. 问：为什么说“驱动签名 + 最小内核代码面”是工程重点？
答：内核一旦失守影响全机。驱动签名、严格 IOCTL 参数校验、减少内核驻留逻辑、把复杂解析放回用户态，是降低高危漏洞面的关键手段。

25. 问：企业侧如何构建可落地的 Windows 防护闭环？
答：基线加固（补丁/策略）+ 应用控制（白名单）+ 行为检测（EDR）+ 取证审计（日志链路）+ 自动化处置（隔离/回滚）。只做单点防护通常挡不住真实攻击链。

26. 问：如果让你设计一个“可解释”的终端检测能力，你会怎么做？
答：先定义事件模型（进程、模块、句柄、网络、注册表、文件），再做多信号关联和风险评分，输出“证据链”而不是仅给结论，便于安全运营做研判与处置。

27. 问：面试里经常追问“防护与误报”的平衡，如何回答更工程化？
答：分层策略（默认阻断高危、低危先告警）、灰度发布、回滚机制、白名单生命周期治理、规则质量指标（检出率/误报率/处置时延）持续迭代。

28. 问：Windows 安全岗位常见深入追问有哪些？
答：
- 解释一次对象访问检查的完整调用链（用户态到内核态）。
- 说清 token theft/impersonation 的前提与防御点。
- 如何识别 DLL 注入、远程线程、APC 注入、反射加载等行为差异。
- 什么时候用内核回调，什么时候留在用户态，如何评估稳定性风险。
- 给一个真实攻防案例，说明你如何从告警到证据固化再到规则修复。
