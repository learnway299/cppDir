## 常见面试考察与解答

1. 问：Chromium 多进程模型核心价值是什么？  
答：通过进程隔离提升稳定性和安全性，单个渲染进程崩溃不影响浏览器主进程，且便于权限最小化。

2. 问：Blink 在 Chromium 中主要负责什么？  
答：负责渲染引擎核心能力，包括 DOM/CSS 解析、布局、绘制、事件分发等页面渲染流程。

3. 问：WebKit 与 Blink 的关系？  
答：Blink 是从 WebKit 分支演进出的渲染引擎；面试通常考你对两者架构共性与实现差异的理解。

4. 问：从 URL 输入到页面展示，核心链路怎么讲？  
答：导航请求 -> 资源加载 -> HTML/CSS/JS 解析 -> DOM/CSSOM 构建 -> Layout -> Paint -> Compositing -> 屏幕显示。

5. 问：Android WebView 与 Chrome 有何关系？  
答：现代 Android WebView 基于 Chromium，系统 WebView 组件版本会影响渲染能力与兼容性表现。

6. 问：WebView 常见性能问题有哪些？  
答：首屏慢、白屏、内存占用高、JS 执行卡顿、频繁跨进程通信、资源缓存策略不合理。

7. 问：WebView 首屏优化的常见手段？  
答：预热进程与内核、复用 WebView、资源本地化与缓存、延迟非关键 JS、减少首屏重排重绘。

8. 问：JS 引擎性能优化通常从哪里入手？  
答：减少热点路径对象分配、避免多态退化、降低跨语言调用成本、优化 GC 压力与事件循环阻塞。

9. 问：内核定制化开发常见风险？  
答：版本升级成本高、与上游 patch 冲突、兼容性回归、调试复杂度上升，需要严格回归体系。

10. 问：浏览器内核方向如何排查页面卡顿？  
答：先定位 CPU 热点线程，再看渲染管线阶段耗时（脚本/布局/绘制/合成），最后针对瓶颈做定向优化。

11. 问：小程序框架实现机制一般考什么？  
答：双线程模型（逻辑层/渲染层）、通信桥接、生命周期管理、路由机制、渲染更新策略。

12. 问：小程序性能优化常见方案？  
答：减少 setData 粒度、批量更新、虚拟列表、按需加载、缓存策略优化、降低桥接通信频次。

13. 问：Java 与 C++ 在该方向如何协同？  
答：Java 负责 Android 业务层与生命周期管理，C++ 承担内核能力和性能敏感路径，通过 JNI 做桥接。

14. 问：JNI 性能和稳定性关注点？  
答：控制跨边界调用频次、避免局部引用泄漏、线程附着/分离规范化、异常及时处理。

15. 问：该岗位如何考察软素质？  
答：通过项目追问看你是否能跨团队推进复杂问题闭环，包括定位路径、协作方式、数据化结果和复盘质量。

## 高阶性能题补充（系统/算法）

16. 问：对千万级整数做取余操作（模数固定且非 `2^n`），如何做到高性能？  
答：核心是避免慢速除法指令，使用“预计算倒数 + 乘法/移位”的 fastmod 思路。  
- 若模数是编译期常量，现代编译器常会自动把 `%` 优化成乘法与移位。  
- 若模数运行期固定，可在初始化阶段预计算 magic number（如 Barrett reduction、libdivide 思路）。  
- 批量处理时可做 SIMD/循环展开，减少分支并提升吞吐。  
- 若是“只需分桶索引”场景，可结合乘法哈希与一次修正，进一步降低开销。  
结论：固定模数场景优先“乘法化取模”，避免逐元素硬除法。

17. 问：字典 map 的 key 数量约 60 亿，启动时 load 一次，内存太大，如何优化？  
答：这类题默认是“静态、读多写少”字典，思路是去掉通用容器的高额指针/节点开销。  
- 不用 `std::map/unordered_map` 直接全量驻内存；节点和桶开销会非常大。  
- 采用“离线构建 + 启动 mmap”方案：  
  - key 有序存储并压缩（delta + varint/SIMD 压缩）。  
  - 建稀疏索引（每 N 条一个锚点）+ 局部二分查找。  
  - 若需 O(1) 查询，可用最小完美哈希（MPH）+ 紧凑 value 数组。  
- 若仅判断存在性，可前置 Bloom/Xor Filter，减少磁盘/内存访问。  
结论：把“通用 map”转为“只读紧凑结构 + 内存映射”，通常能把内存从不可接受降到工程可用。

18. 问：对 100 亿个 64 位整数排序，机器 16C / 2TB，磁盘不限，怎样最快？  
答：100 亿 * 8B 约 80GB，明显可放内存，最快路线是并行内存排序而非外排。  
- 首选并行 radix sort（基数排序），时间复杂度接近 O(kN)，通常优于比较排序 O(NlogN)。  
- 实现要点：  
  - 多线程分块统计直方图。  
  - 全局前缀和计算桶偏移。  
  - 双缓冲 scatter 回写（NUMA 亲和、顺序内存访问）。  
  - 对有符号 64 位整数先做符号位映射（如 `x ^ 0x8000000000000000ULL`）再排。  
- 仅当数据远超内存时才做外部多路归并；本题不需要。  
结论：该配置下“内存内并行 radix + NUMA 优化”通常是最快方案。
